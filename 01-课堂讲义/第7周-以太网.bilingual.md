### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">四层互联网模型回顾（The 4 Layer Internet Model）</span>

开篇用四层互联网模型（four-layer model，四层模型）图回顾链路层（link layer，链路层）的位置：源端主机（Source End-Host）自上而下为应用层（Application）→ 传输层（Transport）→ 网络层（Network）→ 链路层（Link）；两个路由器（Router）只实现网络层与链路层；目的端主机（Destination End-Host）再逐层上到应用层。链路层负责"最后一跳"：把 IP 分组封装成帧，在主机与路由器、路由器与路由器之间直接传递。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">以太网交换机（Ethernet switch）与通用分组交换机模型</span>

以太网交换机（Ethernet switch，交换机）是斯坦福校园网中连接终端主机与路由器的设备。讲义先给出一个**通用分组交换机（Generic Packet Switch）**的抽象模型（图中重复出现 4 次，强调每个输入端口都有同样的流水线）：

- 分组（Data + 首部 H）到达；
- **查找地址（Lookup Address）**：查转发表（forwarding table，转发表），得到目的端口 / 出链路（Destination / Egress link）；
- **更新首部（Update Header）**；
- **排队分组（Queue Packet）**：进入缓冲区（Buffer Memory，缓冲区内存）中的队列。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">以太网交换机的四步算法（Ethernet Switch）</span>

1. 检查每个到达帧（frame，帧）的首部；
2. 如果以太网目的地址（Ethernet DA，即"MAC 地址"）在转发表中，就把帧转发到正确的输出端口；
3. 如果以太网 DA 不在表中，就把帧**广播（broadcast，广播）**到除入端口外的所有端口；
4. 转发表的表项是通过检查到达分组的以太网**源地址**（Ethernet SA）**学习（learn）**到的。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">互联网路由器的七步算法（Internet Router，Slide 9）</span>

1. 如果到达帧的以太网 DA 属于本路由器，接受该帧；否则丢弃；
2. 检查 IP 版本号（version）与数据报（datagram，数据报）长度；
3. 把 TTL（生存时间）减 1，更新 IP 首部校验和（checksum，校验和）；
4. 检查 TTL 是否等于 0；
5. 如果 IP DA（目的地址）在转发表中，转发到通往下一跳的正确出端口；
6. 找到下一跳路由器的以太网 DA；
7. 创建新的以太网帧并发送。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 把 Slide 8（交换机）与 Slide 9（路由器）并排读，你会发现两者的差异恰好对应第 1 章分层模型中"L2 设备 vs L3 设备"的分工。交换机只认 48 位 MAC 地址，转发表靠**自学习**构建：看到源地址为 $S$ 的帧从端口 $p$ 进来，就记下"$S \leftrightarrow p$"——这本质上是把网络当成一张**未知图**在线反向边追踪：每个帧天然顺着"源到目的"的路径走来，交换机沿路记录"回源方向"，目的地址查不到时就退化为广播（flooding，泛洪）。这与 6.042J 图论中"从生成树去边得到无环子图"的思想遥相呼应：以太网为了消除交换机环路必须跑生成树协议（spanning tree，生成树）， Nick 在期末复习一讲会展开。路由器则要"拆到 IP 层做事"：校验版本与长度、TTL 减 1、重算首部校验和、查最长前缀匹配（longest prefix match，最长前缀匹配）表，最后还要**重新封装**一个新的以太网帧——第 1 章"每一天中一个分组的一生"（day in the life of a packet）里"IP 前进、以太网每跳重写"的画面，就是这两页 slide 的机械实现。注意第 3 步只更新 IP 首部校验和，因为 TTL 是 IP 层唯一每跳变化的字段。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">以太网帧格式（Ethernet Frame Format）</span>

帧的字段布局（单位：字节）：前导码 Preamble 7 字节 | 帧起始定界符 SFD 1 字节 | 目的地址 DA 6 字节 | 源地址 SA 6 字节 | 类型 Type 2 字节 | 数据 Data 0–1500 字节 | 填充 Pad 0–46 字节 | CRC 4 字节。

1. **前导码（Preamble，前导码）**：用于训练接收方的时钟恢复（clock recovery，时钟恢复）电路；
2. **帧起始定界符（Start of Frame Delimiter，帧起始定界符）**：指示帧的开始；
3. **目的地址（Destination Address，目的地址）**：48 位全局唯一地址，由网卡制造商分配；其中 1 位区分单播/多播（unicast/multicast），1 位区分本地/全局地址（local/global）；
4. **类型（Type，类型字段）**：指示被封装数据的上层协议（如 IP = 0x0800）；
5. **填充（Pad，填充）**：补零以保证最小帧长；
6. **循环冗余校验（Cyclic Redundancy Check，循环冗余校验）**：用于检测比特差错的校验序列。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">以太网的起源：共享"介质"</span>

- 以太网（至少在最初）是**多台主机共享一条公共电缆**（"介质"，medium）的例子；
- 要共享介质，就必须决定**谁在什么时候可以发送**；
- 这催生了一类通用协议：介质访问控制协议（Medium Access Control Protocols，介质访问控制协议），简称 MAC 协议。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">CSMA/CD 协议</span>

CSMA/CD（Carrier Sense Multiple Access with Collision Detection，载波侦听多路访问/冲突检测）：所有主机在**同一条信道**上收发，分组长度可变。当主机有分组要发送时：

1. **载波侦听（Carrier Sense，载波侦听）**：发送前先检查线路是否空闲；
2. **冲突检测（Collision Detection，冲突检测）**：尽快检测冲突。一旦检测到冲突，**立即停止发送**；等待一段**随机时间**后回到第 1 步。

这一"随机等待"策略称为**二进制指数退避（binary exponential backoff，二进制指数退避）**。🎥 *CS144 教授在视频中解释: "这个随机时间被称为二进制指数后退，它只意味着随着给定包的碰撞次数增加，后退的次数也会增加"*（字幕来源：099 - p98 7-5 Physical and Link - Principles MAC and CSMACD.zh.srt）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">CSMA/CD 的分组大小要求（Packet size requirement）</span>

考虑一条总线上的主机 A、B、C、D（A 在最左端，D 在最远端，单程传播时延 $L/c$，其中 $L$ 为总线长度、$c$ 为信号传播速率）：

- $t = 0$：A 开始发送；
- $t = L/c - \varepsilon$：就在 D 准备发送的瞬间，A 的信号尚未到达 D；
- $t = L/c$：D 开始发送，双方信号相向而行；
- $t = 2L/c$：**A 第一次知道发生了碰撞**。

因此：只要 A 的发送持续时间足够长，它就必然能在**自己还在发送时**检测到碰撞。保证这一点的条件是：A 发送一个分组的传输时长不小于往返传播时延的两倍，即

```math
\frac{P}{R} \geq \frac{2L}{c}
```

（其中 $P$ 为分组长度、$R$ 为链路速率。）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">CSMA/CD 最小分组长度（Min packet size requirement）</span>

为了让端主机在**发完一个分组之前**就能检测到碰撞，必须满足：

```math
\frac{P}{R} \geq \frac{2L}{c} \quad\Longleftrightarrow\quad P_{\min} = \frac{2LR}{c}
```

（其中 $P$ 是分组大小。）

**例**：取 $R = 10\,\text{Mb/s}$，$L = 10{,}000\,\text{m}$，$c = 2 \times 10^8\,\text{m/s}$：

- $2L/c = \dfrac{2 \times 10^4\,\text{m}}{2 \times 10^8\,\text{m/s}} = 10^{-4}\,\text{s} = 100\,\mu\text{s}$
- $P_{\min} = R \cdot \dfrac{2L}{c} = 10^7\,\text{b/s} \times 10^{-4}\,\text{s} = 1{,}000\,\text{bits}$

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条最小帧长公式是整个 CSMA/CD 时代最精妙的设计约束，值得从第一性原理推一遍：碰撞检测的本质是"边发边听"，而电信号跑完往返全程需要 $2L/c$；如果你 $P/R$ 秒就发完了，信号还没绕回，你会误以为发送成功——**检测窗口必须覆盖最坏情况的往返时延**。例子里 10 Mb/s、10 km 的总线要求最小帧 1000 位，注意两个张力方向：速率 $R$ 越高，同时间内发出的比特越多，最小帧越长；距离 $L$ 越长，往返时延越大，最小帧也越长。把数字代进去算一下千兆以太网（$R$ 扩大 100 倍）就知道为什么它撑不住 10 km 总线——工程上只能把网段砍短到几百米甚至引入"载波延伸"，最终干脆用交换机 + 全双工取代共享总线，让冲突从物理上不可能发生，CSMA/CD 随之退役。随机退避则可以套上概率论：第 $i$ 次碰撞后从 $\{0, \dots, 2^k - 1\}$（$k = \min(i, 10)$）均匀抽一个时隙，冲突双方大概率抽到不同值而错开——这正是"指数退避"名字的由来，与 TCP 超时重传的指数退避（第 2 章）异曲同工。历史注：1972 年 Metcalfe 在 Xerox PARC 画下第一版以太网（当时叫 Alto Aloha Network），1980 年成为 DIX 标准雏形，1983 年定为 IEEE 802.3——共享介质的"原始以太网"早已消失，但帧格式沿用至今。
