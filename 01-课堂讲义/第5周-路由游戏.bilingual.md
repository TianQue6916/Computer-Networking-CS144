### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">路由器逐个转发 IP 数据报</span>

1. 路由器以 IP 地址为键查找 forwarding table（转发表）；
2. 然后把数据报发送给"离目的地更近"的下一台路由器。

<span style="color:#00838f;">**互联网逐跳（hop-by-hop）转发数据报：每台路由器只需要知道 next hop（下一跳），不需要知道全路径。**</span>

- 图示：数据分组（Data）从 A 出发，逐跳前进到 B。三台路由器各自的 forwarding table（转发表）如下（IP 地址 → 下一跳）：

| 路由器 | 到 A 的下一跳 | 到 B 的下一跳 | 到 C 的下一跳 | 到 D 的下一跳 |
|---|---|---|---|---|
| 路由器一 | A（直连） | R4 | R4 | R4 |
| 路由器二 | A（直连） | R2 | R3 | R3 |
| 路由器三 | R3 | B（直连） | R3 | R3 |

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 表中每一列是一个目的主机（destination host）A、B、C、D，表内的值是该路由器为到达这个目的地应把分组交给的 next hop（下一跳）；"直连"表示该目的地直接接在本路由器上（directly connected，无需再经其他路由器转发）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">路由器怎么知道该用哪张 forwarding table（转发表）？</span>

- 你能想出哪些技术？

以下是三种办法：

1. **flooding（洪泛）**：每台路由器把到达的分组发给每一个邻居；
2. **source routing（源路由）**：终端主机在（每个分组的）首部里列出沿途要访问的路由器；
3. **distributed algorithm（分布式算法）**：路由器互相交谈，用聪明的算法构造 forwarding table（转发表）。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这个课堂游戏实际上是 Bellman-Ford 算法（一种求最短路径的经典算法）的分布式实现：每个节点只维护"到目标的最优估计 + 下一跳"，信息通过邻居间的喊话逐轮扩散。CLRS（《算法导论》（Introduction to Algorithms）四位作者 Cormen、Leiserson、Rivest、Stein 姓氏首字母的合称）里的 Bellman-Ford 对每条边做 $|V|-1$ 轮 relaxation（松弛，即反复检查"经由某个节点能否得到更短的路径、能则更新距离估计"这一操作），游戏里的"轮次"就是松弛轮数——从源头 1 号出发，可达性信息每轮传播一跳，$k$ 轮后所有 $k$ 跳内可达的节点都拿到正确值，这与 6.042J（MIT 的《计算机科学数学》（Mathematics for Computer Science）课程代号）里 BFS（breadth-first search，广度优先搜索，按离起点由近到远逐层扩展的搜索）按层扩展完全同构（BFS 的层就是最短跳数）。游戏用跳数作为代价，所以它是无权最短路；一旦边权各不相同，就轮到 Dijkstra 算法（每次挑当前距离最小的节点来"确定"答案的求最短路径算法）登场——本讲义后半正是从跳数版本平滑过渡到带权版本。你还能从游戏里直观看到 distance vector protocol（距离向量协议，即每个路由器维护一张"到各目的地的距离"表、并与邻居交换这张表来逐轮收敛的分布式路由协议）的两大代价：坏消息（链路断开）传得慢，且每个节点都要为每个目的地维护状态——这为后面 BGP（Border Gateway Protocol，边界网关协议，互联网上不同自治系统之间交换路由信息的协议）的设计动机埋下伏笔。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">如果每条链路有一个 "cost（代价）" 呢？</span>

- 路径一：$\text{Cost}=1+4+4+2=11$（4 跳）。
- 路径二：$\text{Cost}=4+9=13$（2 跳）。
- 图示：拓扑 A、B、C、D、E、F、G、H，各边权 1、2、4、5、9 等。

**所谓 expensive link（昂贵链路）的可能含义：**

- 它可能非常长。例如一条从欧洲到美国的链路（propagation delay（传播时延）大）。
- 或者它可能非常繁忙。例如它连着 Google 或 CNN（queueing delay（排队时延）大）。
- 或者它可能非常慢。例如 1 Mb/s 而不是 100 Mb/s（transmission delay（传输时延）大）。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "跳数最少"和"代价最低"可能是两条完全不同的路——本页的例子就是证明：4 跳路径代价 11，2 跳路径代价 13，只数跳数就会选错。背后是图论建模的普遍原则：edge weight（边权，即标在每条边上的那个数字）是建模者对"成本"的编码，跳数只是权全为 1 的特例（6.042J 里无权图的 BFS 与带权图的 Dijkstra 的分界正在于此）。"昂贵链路"的三种来源也各有物理含义：很长（propagation delay（传播时延）大）、很忙（congestion（拥塞）使 queueing delay（排队时延）大）、很慢（1 Mb/s 链路的 transmission delay（传输时延）是 100 Mb/s 的 100 倍）——恰好对应第 3 周时延公式的三项：传播、排队、传输。所以 OSPF（Open Shortest Path First，开放最短路径优先，一种在自治系统内部运行、靠洪泛全网拓扑来计算最短路径的路由协议）让管理员给每条链路配置代价，本质上是在问"你想优化什么"：优化吞吐就按带宽倒数定权，优化延迟就按时延定权。还有一层：权一旦随拥塞实时变化，就会引发 route oscillation（路由震荡，即路由选择在几个方案间反复切换、无法稳定下来的现象）——这就是生产网络的链路代价通常静态配置而非实时测量的原因。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这几页演示的是把"跳数游戏"升级为带权游戏后，信息如何继续用分布式方式扩散：路由器 4 广播"我能以代价 15 到达节点 2"，邻居把这个数字加上自己到它一条边的权再转发——这正是 distance vector（距离向量）协议逐跳 relaxation（松弛）的过程，与 CLRS 里 Bellman-Ford 的边松弛一一对应。对照前面 Dijkstra 的页面：link state protocol（链路状态协议，即每个路由器先把整网拓扑洪泛给所有人、再各自独立计算最短路径）是"人人都有全图，各自独立算 Dijkstra"，distance vector（距离向量）是"没有人有全图，大家靠交换距离估计收敛到同一答案"。两种范式各有失败模式：前者要求把链路状态洪泛给全网（带宽开销大、每节点计算 $O((V+E)\log V)$），后者收敛慢且可能形成 routing loop（路由环，即分组在几台路由器之间转圈、到不了目的地），进而出现 count to infinity（数到无穷，即坏消息在距离向量协议里被逐跳加 1、迟迟收敛不了的病态现象）。课堂游戏还能让你亲眼看到收敛速度取决于 network diameter（网络直径，图中两点间最大最短距离），因为信息每轮只能走一跳；这也解释了为什么互联网 AS（Autonomous System，自治系统，即由单一机构管理的一组路由器与网络）内部的网络直径被刻意控制在几跳以内。
