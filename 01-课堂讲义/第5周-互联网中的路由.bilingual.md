# CS144: An Introduction to Computer Networks（计算机网络导论，Stanford Fall 2019）

## 互联网中的路由（Internet Routing）：Dijkstra 的另一种视角

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">标题页与图示</span>

- 主题：Dijkstra 的另一种视角（Another view of Dijkstra...）。
- 纯图示页（slide 2–4）：一个由路由器 R1、R2、R3、R4、R5 组成的拓扑，从 A 到 B；各边标注链路代价（如 3、4、4、2、3、4、2 等）。三页依次展示该网络图的绘制/展开过程，用于引出"最短路径"如何在一张带权图上计算。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 开头的"另一种视角"值得与你在 CLRS 学的版本精确对齐：Dijkstra 维护一个已确定最短路的节点集合，每轮用优先队列取出 dist 最小的未定节点并松弛其邻居，堆实现下复杂度 $O((V+E)\log V)$。它成立的前提是边权非负——网络里的链路代价（传播时延、带宽倒数）天然非负，所以 Dijkstra 是链路状态路由协议（OSPF）的引擎。把算法理解成"按代价递增的顺序一环环向外扩张波前"会很直观，像水波扩散：每轮新确定的节点都是当前波前上离源点最近的那个。与 6.042J 证明过的最短路最优子结构性质（最短路的任何前缀仍是最短路）对照：Dijkstra 的贪心正确性正是最优子结构加上非负权条件的直接推论。而 Bellman-Ford 不需要非负权，代价是 $O(VE)$——这组取舍马上会在域间路由协议 BGP 的故事里重现。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">互联网路由是分层的</span>

<span style="color:#00838f;">**互联网路由是分层的（hierarchical）：所有组织（自治系统，Autonomous System, AS）使用相同的算法（协议）彼此对话。**</span>

- 图示：Stanford University、Cambridge University 等组织通过 CENIC、Internet2 等区域/学术网络互联——每个组织是一个 AS。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "互联网路由是分层的"是全篇最重要的一句话：域内路由（intra-domain）与域间路由（inter-domain）是图论意义上的"图上套图"。把每个 AS 缩成一个点、商业关系当边权，得到一张几千节点的 AS 级图；每个 AS 内部又各自是一张成千上万节点的图，跑自己的最短路算法。这与 6.042J 的组合思想一致：分解是控制复杂度的根本手段。工程动因是规模与信任——全网数十亿前缀、数百万路由器，任何全局算法在计算与通信上都不可行；分层后每台路由器只需知道"去本 AS 内某目的地怎么走"与"出 AS 该交给谁"。下面 traceroute 输出里每一跳都是 AS 边界的体现：SUNet（斯坦福校园网）→ CENIC（加州学术网）→ Internet2（美国学术骨干）→ GEANT（欧洲学术网）→ Janet（英国学术网）→ 剑桥，一条链横穿五六个 AS，每个 AS 只负责自己那一段。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">边界网关协议（Border Gateway Protocol, BGP）</span>

- BGP 邻居（"对等体" peers）之间建立一条 TCP 连接。
- BGP 既不是链路状态（link-state）协议，也不是距离向量（distance-vector）协议。
- 相反，BGP 使用所谓的"路径向量（path vector）"。
- 对每个前缀（prefix），BGP 路由器通告一条到达它的 AS 路径——这就是"路径向量"。通告样例（协议消息原文）：

```
"The network 171.64/16 can be reached via the path {AS1, AS5, AS13}"
```

（含义：网络 171.64/16 可以经由路径 {AS1, AS5, AS13} 到达。）

- 当链路/路由器故障时，该路径向量被"撤回"（withdrawn）。

BGP 补充：

- 带环的路径在本地被检测出来并忽略。
- 本地策略（local policies）在所有已通告路径中挑选首选路径。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> BGP 自称"路径向量"协议，可以把它理解为距离向量的防环加强版。距离向量协议（如 RIP）只通告"去某目的地的距离"，收敛慢且会"数到无穷"（count to infinity）——这正是 CLRS 里 Bellman-Ford 分布式化之后的经典病症；BGP 干脆把整条 AS 路径一起通告，收到通告的路由器只要发现自己已在路径里就拒绝，环路检测从"猜"变成"查"，代价是报文更大、计算更贵。另一个关键差异：Dijkstra/Bellman-Ford 都默认所有节点对"最短"有一致定义，而 BGP 的每个 AS 用本地策略挑选路径——商业利益（后面几页的 customer/peer 关系）常常压倒最短路，所以 BGP 计算的不是图论意义的最短路，而是"符合策略的可行路"。这也解释了为什么 BGP 收敛以分钟计：策略让各节点状态不一致，故障撤回（withdraw）要逐跳传播。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">客户与提供商（Customers and Providers）</span>

- 图示：provider（提供商）— customer（客户）之间的连线承载 IP 流量（IP traffic）。
- <span style="color:#00838f;">客户向提供商付费，请提供商承载自己的分组。</span>

客户—提供商层级（Customer-Provider Hierarchy）：提供商自己也可以是更大提供商的客户，逐级向上形成层级。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">对等互联关系（The Peering Relationship）</span>

- 图示区分两种连接：peer ↔ provider（对等体与提供商，流量放行 traffic allowed）；peer ↔ customer（对等体与客户，流量不放行 traffic NOT allowed）。

对等互联的三条规则：

1. 对等体为彼此的**客户**提供中转（transit）。
2. 对等体之间不为彼此提供中转。
3. 对等体之间（通常）不交换钱（\$\$\$）。

- 于是问题来了：左边一侧的流量怎么才能到达右边一侧？

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">"Tier 1" 提供商</span>

<span style="color:#00838f;">**"Tier 1" 网络是一个"免中转"（transit-free）网络，它与其他所有 Tier 1 网络都对等互联。**</span>

图示：多个 "Tier 1" 网络两两互相对等互联。

**Tier 1 ISP 的定义：**

- <span style="color:#00838f;">定义：一个 Tier 1 ISP 仅凭其免费且互惠的对等互联协议，就能访问整个互联网区域（Internet Region）。</span>
- <span style="color:#00838f;">定义：互联网区域（Internet Region）是互联网网络中通常以国家地理边界为界的一部分。</span>
- 每个互联网区域有自己的 "Tier 1 ISP" 集合。

**石蕊测试（litmus test）：**

"该 ISP 是否需要向任何人付费，才能到达互联网区域内的任一目的地？"——若答案是"否"，它就是 Tier 1 ISP；若答案是"是"，它就是 Tier 2 ISP。
