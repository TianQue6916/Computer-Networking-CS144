## 分组交换：排队模型、公平排队与时延保证（Packet Switching: Queueing, Fair Queueing & Delay Guarantees）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">大纲</span>

1. 端到端时延（end-to-end delay）
2. 排队时延（queueing delay）
3. 简单确定性队列模型（simple deterministic queue model）
4. 速率保证（rate guarantees）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">路由器队列的简单模型</span>

图示（slide 11–13）：一台路由器队列，到达过程 $A(t)$、离开过程 $D(t)$、队列占用 $Q(t)$，链路速率 $R$。

- $A(t)$：<span style="color:#00838f;">截至时刻 $t$ 累积到达的字节数。</span>
- $D(t)$：<span style="color:#00838f;">截至时刻 $t$ 累积离开的字节数。</span>
- 性质：
  1. $A(t)$、$D(t)$ 均单调非减（non-decreasing）；
  2. $D(t) \le A(t)$。

<span style="color:#00838f;">**队列占用（queue occupancy）：$Q(t) = A(t) - D(t)$。**</span>

<span style="color:#00838f;">**排队时延（queueing delay）$d(t)$：在队列按先到先服务（first-come-first-served, FCFS）的前提下，时刻 $t$ 到达的字节在队列中度过的时间。**</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这套累积曲线记号是排队论的标准语言，值得花一分钟消化：$A(t)$ 与 $D(t)$ 都是单调非减的阶梯函数（分组到达与离开都是离散事件），队列占用就是两条曲线之间的垂直距离 $Q(t)=A(t)-D(t)$，而排队时延是水平方向的距离 $d(t)$。"垂直距离 = 占用、水平距离 = 时延"这一对偶关系正是利特尔法则 $Q=\lambda d$ 的几何来源：当两条曲线近似平行（系统进入稳态）时，垂直距离与水平距离成固定比例，比例正是到达率 $\lambda$。你在概率论里学的泊松过程（Poisson process）就是 $A(t)$ 最常用的随机模型；而本讲刻意只做确定性假设，把随机性全部装进"上界"里。这种"先确定性、后随机"的建模次序，与你在 6.006 里先学确定性算法再学随机化算法的次序是一样的：先把结构看清楚，再谈统计。

### <span style="color:#2471a3;">**[example]**</span> <span style="color:#c0392b;">例题一：存储转发（store & forward）</span>

**题目：** 每 1 秒有一个 500 比特的分组到达队列，到达（发送）速率为 10,000 b/s；队列的最大离开（服务）速率为 1,000 b/s。队列的平均占用是多少？

> **解答：** 在每个重复的 1 秒周期内，队列先以 10,000 b/s 的速率填充 0.05 s，然后以 1,000 b/s 的速率排空 0.5 s。在前 0.55 s 内，平均队列占用为 250 比特。每个周期中队列还有 0.45 s 完全为空，因此长程平均队列占用为 $(0.55 \times 250) + (0.45 \times 0) = 137.5$ 比特。

### <span style="color:#2471a3;">**[example]**</span> <span style="color:#c0392b;">例题二：直通（cut through）</span>

**题目：** 同样地，每 1 秒有一个 500 比特的分组到达，到达速率为 10,000 b/s；最大离开速率为 1,000 b/s。这次采用直通转发，队列的时间平均占用是多少？

> **解答：** 在每个重复的 1 秒周期内，前 0.05 s 内队列以 10,000 b/s 填充、同时以 1,000 b/s 排出，净涨至 $500-50=450$ 比特；随后以 1,000 b/s 排空 0.45 s。在前 0.5 s 内，平均队列占用为 225 比特。每个周期中队列有 0.5 s 为空，因此平均队列占用为 $0.5 \times 225 + 0.5 \times 0 = 112.5$ 比特。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这两道例题的计算里藏着"忙期平均 vs 长程时间平均"的重要区分：0.55 s 内的 250 比特是"忙期平均"，完整 1 s 周期的 137.5 比特才是容量规划关心的长程平均。计算方法是标准的"曲线下面积除以区间长度"：占用曲线是三角形或梯形，$\overline{Q} = \frac{1}{T}\int_0^T Q(t)\,dt$。这本质上是在算一个随机过程的期望，只是过程被简化成确定性循环。对比两个答案：存储转发（137.5）比直通（112.5）多占 25 比特，因为存储转发让整包 500 比特先到齐再放行，而直通边收边发。顺带一提，10,000 b/s 发送 500 比特只需 0.05 s，随后有约 0.95 s 空闲——这种"成批到达、长空闲"的模式在概率论里对应批量到达过程，也是数据中心流量的真实写照（第 5 周客座讲座里的 incast 就是它的极端形式）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">如果有些分组比另一些更重要呢？</span>

- 默认情况下，交换机与路由器使用 FIFO（先进先出，aka FCFS）队列：来自不同入口端口的分组进入缓冲区（缓冲大小 $B$、服务速率 $R$），按到达顺序离开。
- 但有些分组确实更重要，例如：
  1. 维持网络正常运转的控制流量（如携带路由表更新的分组）；
  2. 来自特定用户的流量（如付费更多的客户）；
  3. 属于特定应用的流量（如视频会议）；
  4. 去往/来自特定 IP 地址的流量（如紧急服务）；
  5. 对时间敏感的流量（如时钟更新）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">流（Flows）</span>

讨论优先级时，把共享同一组属性的分组统称为一个"流（flow）"会很方便。例如：

1. 属于同一条 TCP 连接的所有分组构成的流——由元组（tuple）标识：TCP 端口号、IP 地址、TCP 协议；
2. 所有发往斯坦福的分组构成的流——由属于前缀 171.64/16 的目的 IP 地址标识；
3. 所有来自 Google 的分组构成的流——由属于 Google 所拥有的前缀集合的源 IP 地址标识；
4. 使用 http 协议的网页分组构成的流——由 TCP 端口号 = 80 标识；
5. 属于金牌（gold-service）客户的分组构成的流——通常通过标记 IP 首部的 TOS（type of service，服务类型）字段来标识。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">严格优先级（Strict Priorities）</span>

大纲：1. 严格优先级；2. 加权优先级与速率保证。

<span style="color:#00838f;">**"严格优先级"意味着：只有当所有更高优先级的队列都为空时，一个队列才会被服务。**</span>

图示：高优先级流与低优先级流分别进入各自的队列，调度器总是先服务高优先级队列。

严格优先级需要注意的事项：

1. 严格优先级可以与任意数量的队列一起使用。
2. 严格优先级的定义如上：某队列仅当所有更高优先级队列都空时才被服务。
3. 最高优先级的流"看到"的网络里仿佛没有任何低优先级流量。
4. 高优先级流可能永久性地饿死（block）低优先级流。要尽量限制高优先级流量的总量。
5. 如果你无法控制高优先级流量的总量，这套机制大概率不会好用。
6. 或者，当你真正想要的是加权（而非严格）优先级时，它也不适用。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">如何给出加权（而非严格）的优先级？</span>

**尝试平等对待各流（round-robin 式按包轮转）：** 图示表明——虽然每个流都能以相同的"分组速率"发送，但由于包长不同，各流得到的"数据速率"相差甚远（大包流占便宜）。

**按比特逐位调度各流（bit-by-bit）：** 图示表明——现在每个流获得相同的数据速率，但我们已经不再拥有"分组交换"了（分组被切碎，无法发送）。

**能否兼得两者之长？** 即：既保持分组交换，又按比特记账？

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">公平排队（Fair Queueing）</span>

<span style="color:#00838f;">**公平排队：分组按照它们在"逐比特轮转"方案中的完成顺序被发送。**</span>

图示（slide 33）：多个流的分组在调度器内按各自"逐比特完成时间"排序后依次发出。那么：这能给出公平（即均等）的数据速率份额吗？

**能！（Yes!）**

1. 可以证明：公平排队下，一个分组的离开时间不晚于"逐比特方案"下超过 $L_{max}/R$ 秒——其中 $L_{max}$ 是最大分组长度，$R$ 是出链路的数据速率。
2. 在极限意义下，两个流获得均等的数据速率份额。
3. 该结论可以推广到任意数量的流共享一条链路。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 公平排队的证明思路值得与 CLRS 对照理解：算法给每个分组计算一个"虚拟完成时间"——先假设带宽可以像流体一样无限细分（理想流体模型），按逐比特轮转给每个流每轮发一个比特，问该分组的最后一个比特会在虚拟时间轴的哪一刻发完；真实系统再按虚拟完成时间的顺序发送分组。定理保证真实离开时间不晚于理想值加 $L_{max}/R$：最坏情形是发包中途被一个最大长度分组"插队"，多等一个整包的发送时间。这是 1990 年 Demers、Keshav、Shenker 提出的算法（原始论文即本页脚注引用），是网络公平性的基石，max-min fairness（最大最小公平）就由它近似实现。与你在 6.006 学的优先队列对照：调度器就是一个"按虚拟完成时间取最小值"的优先队列，每包更新 $O(\log n)$；工程上真正的难点在于每包都要维护虚拟时钟与逐流状态，所以现实中常使用近似的 Deficit Round Robin（DRR）来降低复杂度。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">加权公平排队（Weighted Fair Queueing, WFQ）</span>

如果每个流应得的链路份额不同——即"加权公平份额"——怎么办？

<span style="color:#00838f;">**加权公平排队：对任意数量的流、任意包长混合，(1) 用"加权逐比特"方案为每个分组计算离开时间；(2) 按离开时间的升序转发分组。若权重 $\varphi_i$ 满足 $\sum_{i=1}^{N} \varphi_i = 1$，则流 $i$ 保证获得至少 $\varphi_i R$ 的速率。**</span>

图示（slide 36）：两条流分别占 3/4 与 1/4 的份额，分组仍按加权逐比特完成顺序发送。

WFQ 架构（slide 38/45）：到达不同入口端口的分组 → 按"流"分类（classify packets into flows）→ 分组调度器（packet scheduler）按权重 $\varphi_i$ 以速率 $R$ 调度 → 流 $i$ 保证至少获得速率 $\varphi_i R$。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">我们能否保证分组穿越整个分组交换网络的时延？</span>

**时延保证的直觉（intuition）：**

- 图示：A 经 $l_1,r_1$、$l_2,r_2$、$l_3,r_3$、$l_4,r_4$ 到 B。
- <span style="color:#00838f;">端到端时延 $D = \sum_i \frac{l_i}{c} + \sum_i \frac{p}{r_i} + \sum_i Q_i(t)$：传播项（固定）+ 传输项（固定）+ 排队项（可变）。</span>
- 下列数值是固定的（或在我们的控制之下）：$p$、$c$、$l_i$ 与 $r_i$。如果我们知道排队量 $Q$ 的上界，就知道端到端时延的上界。

**队列占用的上界：**

<span style="color:#00838f;">**若队列缓冲区大小为 $b$、服务速率为 $R$，则任何分组在队内等待不超过 $b/R$。**</span>

- 例子：如果一个分组到达一个大小为 100 万比特的 FIFO 队列，队列以 1 Gb/s 被服务，那么该分组保证在 $b/R = 1\,\text{ms}$ 内离开。

**为什么这仅仅是直觉……**

1. 它没有告诉我们当队列已满（到达速率超过服务速率）时会发生什么：分组会被丢弃吗？
2. 它把共享一个队列的所有分组当成一个大流看待，无法给每个流不同的端到端时延。
3. 问：如何给每个单独的流一个时延上界？

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 注意这一页的推理结构与算法课里"最坏情形分析"如出一辙：我们不问"平均时延多少"，只问"最坏不超过多少"。队列最多积压 $b$ 比特、服务速率 $R$，最坏排队时间自然是 $b/R$——这是一个完全确定性的界，不需要任何概率假设，与你用切诺夫界（Chernoff bound）给随机变量定上界的思路互补：切诺夫界给出"以高概率不超过"，这里是"永不辜负"的硬界。代价同样明显：为了硬界，队列必须预留缓冲 $b$、必须保证服务速率，链路利用率会显著下降——这正是经典容量规划里"确定性 QoS 贵、统计复用省"的根本权衡。后面"实践中为何不用"一页会回到这个问题。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">为每条流限定端到端时延</span>

给单个流做端到端时延界定（bounding end-to-end delay）：

1. 为该流分配一个大小为 $b$ 的队列；
2. 为该流指定一个 WFQ 服务速率 $\varphi R$。

<span style="color:#00838f;">**则单跳排队时延至多 $b/(\varphi R)$；长度为 $p \le b$ 的单个分组的端到端时延 $\le$ 各跳传播项 + $p/(\varphi R)$ + 各跳 $b/(\varphi R)$。**</span>

**如果该流的两个分组背靠背（back-to-back）进入网络呢？（一个"突发" burst）**

1. 如果两个分组相距较远，各队列会在第二个分组到达前排空第一个——一切正常，时延公式成立。
2. 如果两个分组紧挨着形成"突发"，它们可能以快于 $\varphi R$ 的速率到达，队列可能溢出并丢包。
3. 某些场景下丢包也许可以接受；但若要界定**所有**分组的端到端时延，就必须处理突发。怎么办？

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">漏桶调节器（Leaky Bucket Regulator）</span>

限制"突发性（burstiness）"：

- 图示（重复 3 页）：令牌（tokens）以恒定速率 $r$ 生成并注入令牌桶；令牌桶容量为 $s$；分组从"入（Packets In）"到"出（Packets Out）"；<span style="color:#00838f;">当且仅当桶中有令牌时才允许发送分组。</span>

- 累计曲线图：调节器的输入 $\mathrm{In}(t)$ 与输出 $\mathrm{Out}(t)$（bits 随时间变化）。<span style="color:#00838f;">任意长度为 $t$ 的时段内可发送的比特数上界为 $\sigma + \rho t$（桶深 $\sigma$ + 令牌速率 $\rho \times t$）。因此它也叫"$(\sigma, \rho)$ 调节器"。</span>

**一个很妙的定理（cool theorem）：**

- <span style="color:#00838f;">如果到达队列的流量是 $(\sigma, \rho)$ 受约束的（$(\sigma,\rho)$-constrained），并且队列以速率 $R > \rho$ 服务（WFQ 保证 $\varphi R > \rho$），那么离开流量同样满足 $(\sigma, \rho)$ 约束——这意味着到达下一台路由器的流量也满足该约束。</span>
- 若 $R > \rho$ 且 $\varphi R > \rho$，则该流的所有分组穿过第一台路由器的时延 $\le b/(\varphi R)$。

**全部拼起来（putting it all together）：** 若沿途每跳均满足 $R > \rho$ 且 $\varphi R > \rho$，则每个长度为 $p$ 的分组的端到端时延满足

```math
D \;\le\; \sum_i \frac{l_i}{c} \;+\; \frac{p}{\rho} \;+\; \sum_{\text{hops}} \frac{b}{\varphi R}
```

- 换句话说（每跳装上漏桶 $(\sigma_i, \rho)$ 与 WFQ $(b_i, \varphi_i R)$）：只要每跳链路速率 $r_i > \rho$、每跳 WFQ 服务速率 $\varphi_i R_i > \rho$，那么端到端时延就是有限项之和：传播 + $p/\rho$ + 各跳 $b_i/(\varphi_i R_i)$。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 漏桶调节器与 TCP 慢启动/AIMD 形成有趣的对照：TCP 的拥塞控制是"事后反应式"——先制造拥塞信号再退避，窗口形状由反馈环路决定；漏桶是"事前整形式"——直接把进入网络的流整形为 $(\sigma,\rho)$ 形状：任意长度 $t$ 的区间内最多发 $\sigma+\rho t$ 比特，桶深 $\sigma$ 决定允许的突发上限，令牌速率 $\rho$ 决定长程平均速率。那个"妙定理"（输出也满足同样的 $(\sigma,\rho)$ 约束）是级联推导的核心：只要每跳 WFQ 服务速率都大于 $\rho$，这条约束就像数学归纳法一样逐跳传递，于是端到端时延界是有限项之和——每跳贡献 $b/(\varphi R)$。这与概率论里"不追求精确分布、只追求可依赖的硬上界"的思路同源。虽然公共互联网最终没有提供这种服务（见下一页），但同样的 $(\sigma,\rho)$ 语言活在了今天数据中心流量工程与 API 限流器（你调用云服务时的 rate limiter）里。

### <span style="color:#2471a3;">**[example]**</span> <span style="color:#c0392b;">例题：给一条流做速率与时延保证</span>

**题目：** 在下面的网络中，我们要给一个应用流提供 10 Mb/s 的速率、以及 1,000 字节分组低于 4.7 ms 的端到端时延。漏桶调节器应取什么参数？路由器需要多大的服务速率与缓冲区？（假设传播速度 $c = 2\times 10^8$ m/s。）

- 图示：A ——（10 km，1 Gb/s）——（100 km，100 Mb/s）——（10 km，1 Gb/s）—— B，A 处装漏桶 $(\sigma, \rho)$ 调节器，两台路由器各跑 WFQ。

> **解答：** 时延的固定成分是 $(120\,\text{km}/c) + 8{,}000\,\text{bits}\times\left(\frac{1}{1\,\text{Gb/s}} + \frac{1}{100\,\text{Mb/s}} + \frac{1}{1\,\text{Gb/s}}\right) = 0.7\,\text{ms}$，剩下 4 ms 留给路由器队列。把 2 ms 分给每台路由器，意味着每台路由器的队列不超过 $2\,\text{ms}\times 10\,\text{Mb/s} = 20{,}000$ 比特（即 2,500 字节）。因此，主机 A 的漏桶调节器应取 $\rho = 10\,\text{Mb/s}$、$\sigma \ge 20{,}000$ 比特。每台路由器的 WFQ 应设置为 $\varphi \ge 10/100$，且该流的队列容量至少 2,500 字节。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">实践中呢？</span>

- 虽然几乎所有的网络设备都实现了 WFQ（甚至你家里的 WiFi 路由器可能都有！），但公共网络并不提供控制端到端时延的服务。
- 为什么？
  - 它需要端到端协调所有路由器。
  - 在大多数网络中，"过度配置（over-provisioning）+ 优先级"的组合已经足够好。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">小结</span>

1. 如果我们知道了队列的大小与服务速率，就能界定穿过它的时延。
2. WFQ 让我们得以挑选队列的服务速率。
3. 结合上面两条：只要不丢包，我们就能控制端到端时延。
4. 为了防丢包，可以用漏桶调节器控制进入网络的流的"突发性"。
