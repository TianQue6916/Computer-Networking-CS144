### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">一个分组跨越链路的总时延（Slide 4）</span>

**总时延（Total time to send a packet across a link）**：从第一个比特被发出，到最后一个比特到达的总时间。

```math
d = \frac{l}{c} + \frac{p}{r}
```

其中：$l$ 为链路长度、$c$ 为传播速率（propagation speed），$l/c$ 是传播时延（propagation delay，传播时延）；$p$ 为分组长度、$r$ 为链路速率（bits/s），$p/r$ 是传输时延（transmission delay，传输时延）。

**例**：一个 100 bit 的分组以 10 Mb/s 在 1 km 链路上发送，需要 $10 + 5 = 15\,\mu s$（传输时延 $100/10^7 = 10\,\mu s$，传播时延 $1000/(2\times10^8) = 5\,\mu s$）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">香农容量（Shannon Capacity，Slide 13）</span>

- 香农容量代表我们通过一个信道**无差错传输的最大速率**——即最大数据速率，在某些温和假设下：

```math
C = B\,\log_2\!\left(1 + \frac{S}{N}\right)
```

- 换句话说，它**只取决于带宽 $B$ 和信噪比（Signal-to-Noise Ratio，信噪比）$S/N$**！
- （课程推荐：EE376A 信息论。Wow.）

🎥 *CS144 教授在视频中解释: "通过特定通道的通道容量或每秒可以发送的位数……等于两个对数一加上信号与噪声比，其中 b 是你通信的带宽……这个限制被称为香农极限"*（字幕来源：095 - p94 7-1 Physical and Link Principles - Shannon Capacity and Modulation.zh.srt）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 香农容量公式是"概率论约束工程极限"最著名的例子，值得用你学过的知识拆开。为什么带 $\log_2$？把信道想象成每次"使用"发送一个幅度/相位组合（symbol，符号），带噪信道里星座点必须隔得足够远才不会认错；信号功率 $S$ 越大，能摆开的点数按几何级数增长，而 $k$ 个点恰好编码 $\log_2 k$ 比特——指数容量对应对数比特数。为什么是 $1 + S/N$？这来自把噪声建模为加性高斯随机变量的信息论推导，"1"代表无信号时信道仍被噪声占据的那个自由度。你在概率论里学过期望与大数定律：信道编码正是靠把足够多的比特绑成一个长码块，让"平均译码错误"收敛到任意小——这是大数定律从"抛硬币"到"跨洋通信"的直接应用。香农在 1937 年的硕士论文里就把布尔代数变成电路设计工具（你数字电路里学的卡诺图那一脉），1948 年又给了通信一个理论极限；对链路设计者，$C$ 是一条"物理天花板"——第 1 章讲过链路带宽是四层模型里时延-带宽积的分子，而它自己又臣服于这条公式。想深究可以选 Stanford EE376A（信息论）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">模拟信号（Analog signals）</span>

- 频率（Frequency）= 1/波长；
- 带宽（Bandwidth）：频率范围的大小；
- 相位（Phase）：波峰在波长内的位置。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">On-Off Keying（OOK，Slide 13）</span>

- 一个频率；
- 2 个幅度（有电=1，无电=0）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">发送 0 和 1 的三种方式（Slide 14）</span>

- 频移键控（Frequency Shift Keying，FSK）：改变频率；
- 幅移键控（Amplitude Shift Keying，ASK）：改变幅度；
- 相移键控（Phase Shift Keying，PSK）：同一频率、同一幅度，改变相位（功率与波长均无变化）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">模拟信号中的相位（Phase，Slide 15/16）</span>

三幅正弦波形图对比（横轴为时间，单位秒）：三条曲线频率相同、幅度相同，仅相位不同——分别相差 $0°$、$-90°$（$-\pi/2$）、$-180°$（$-\pi$）、$-270°$（$-3\pi/2$）。结论：**同频率、同幅度、不同相位**的波形是可以区分的三（四）个合法状态——这就是把相位当作信息载体的依据。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">正交相移键控 QPSK（Slide 18）</span>

QPSK（Quadrature Phase Shift Keying，正交相移键控）：星座图上四个等幅点，相位分别为 $-45°$、$-135°$、$-225°$、$-315°$（即 $\pm\pi/4$ 与 $\pm 3\pi/4$），半径为 $R$。

1. 对每个符号：幅度是多少？相位是多少？
2. 把每个符号表示成比特（QPSK 每符号 2 比特）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">正交幅度调制 16-QAM（Slide 19）</span>

16-QAM（Quadrature Amplitude Modulation，正交幅度调制）的四个设计问题：

1. 需要多少个符号（点）？
2. 幅度有几档变化？
3. 相位有几档变化？
4. 每个符号承载多少比特？（16 = $2^4$，每符号 4 比特。）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">用 16-QAM 发送 32 位字的例子</span>

32 位字 `1100 1001 0100 1110 1100 0110 1100 1111` 按 4 位一组切成 8 个符号（编号 0–7），每个符号查 16-QAM 星座得到 (幅度, 相位) 并依次发送。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">本讲用到的调制方式谱系（Slide 21）</span>

| 调制方式 | 应用 |
|---|---|
| ASK/OOK | 有线以太网（wired Ethernet） |
| FSK | 蓝牙（Bluetooth） |
| BPSK | 802.11 a/b/g/n（WiFi） |
| QPSK | 802.11 a/b/g/n、LTE |
| 16-QAM | 802.11 a/b/g/n、LTE |
| 64-QAM | 802.11 a/b/g/n、LTE、5G |
| 256-QAM | 5G |
| 1024-QAM | 家庭电力线通信（home powerline communication） |
| 32768-QAM | ADSL（长距离电话线上的数字数据） |

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这张谱系表其实是一条"星座点数竞赛"的路线图，可以从第一性原理读懂它的排序逻辑：16-QAM 有 $16 = 2^4$ 个点，每符号 4 比特；32768-QAM 有 $2^{15}$ 个点，每符号 15 比特——点越多每符号塞的比特越多，但相邻点的间距越小，对噪声越敏感。于是表中出现了漂亮的对应：有线以太网功率充足、噪声小，用最简单的 OOK 就够；ADSL 走的是又老又长、衰减严重的电话线，却敢用 32768-QAM，正是因为它按线路质量**自适应**选择星座、且子信道极窄（$S/N$ 逐子信道优化）；无线 WiFi 与 5G 则按当前信道质量在 QPSK 与 256-QAM 之间动态切换——这就是你在手机设置里看到"信号格数"背后的调制协商。回头看香农公式 $C = B\log_2(1+S/N)$：调制的任务就是把 $\log_2(1+S/N)$ 这个"每符号比特预算"尽可能花满。一个数字直觉：QPSK 与 16-QAM 在相同符号率下速率差 2 倍，但后者要求约 5 dB 更高的信噪比——工程永远在"更快"与"更稳"之间买保险。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">时钟问题（Clocks）</span>

第二部分主题：收发双方时钟不一致怎么办。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">如果我们不知道发送方的时钟（Slide 23）</span>

图示：发送方以自己的 TX 时钟（周期 $T_{Tx}$）发送数据；接收方用自己的 RX 时钟（周期 $T_{Rx}$）采样。若两者有偏差，采样点会逐渐漂移，直至完全错过（Missed!）一个比特。

- 时钟误差通常用**百万分率（parts per million，ppm）**而不是百分比来表示。
- 如果 RX 时钟比 TX 时钟慢 $p\%$，那么：

```math
T_{Rx} = T_{Tx}\left(1 + \frac{p}{100}\right)
```

- （数值示例，原文乱码）偏差累积约 56 个比特时间（bit time）后，RX 时钟将完全错过一个比特。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">网络链路上的同步通信</span>

图示架构：TX 时钟域（10 MHz 时钟，±100 ppm）→ 触发器（Flip-Flop）→ 网络链路 → 接收端的**时钟恢复单元（Clock Recovery Unit）**从信号中还原"发送方的时钟"→ RX 时钟域（10 MHz 时钟，±100 ppm）中的触发器用恢复出的时钟采样数据。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">为时钟恢复而编码（Encoding for clock recovery）</span>

图示：数据与其隐含时钟、以及采样点（Sampling points）的对应关系。核心结论：**如果时钟不单独传一条线，数据流本身就必须有足够的跳变（transitions）**，接收方才能判断"该何时采样"。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">时钟恢复编码示例 #1：10 Mb/s 以太网的曼彻斯特编码</span>

数据 `0 1 1 0 1 0 1 1` 与其"曼彻斯特编码（Manchester Coding，曼彻斯特编码）"波形对照（编码后每个比特周期中间必有一次跳变，跳变本身携带时钟）。

**优点**：

- 保证每个比特周期至少一次跳变（时钟信息充足）；
- 确保直流平衡（d.c. balance，即高电平与低电平数量相等）。

**缺点**：

- 最坏情况下所需带宽加倍。

随后把前面 OOK 例子中的字节 "176"（`10110000`）用曼彻斯特编码重新画了一遍：数据 `1 0 1 1 0 0 0 0` → 编码后的信号波形（Encoded Data / Manchester / Signal 三行对照）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">时钟恢复编码示例 #2：4b/5b 编码（Slide 28）</span>

把每 4 比特数据映射为 5 比特码字（例：`0000`→`11110`，`0001`→`01001`，`0010`→`10100`，……）。

**优点**：

- 带宽效率更高（只有 25% 开销，对比曼彻斯特的 100%）；
- 多出来的码字可以用于控制信息（如帧起止）。

**缺点**：

- 跳变更少，时钟恢复稍难一些。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">弹性缓冲区（Elasticity Buffer）</span>

回到"同步通信"那张架构图：即便时钟恢复单元还原出了发送方时钟，RX 时钟域（±100 ppm）与恢复出的发送时钟仍不完全一致——于是需要一个**弹性缓冲区（Elasticity Buffer，弹性缓冲区）**吸收两边速率的微小差异。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">弹性缓冲区的尺寸估算（Slide 30）</span>

以"累计比特数 vs 时间"画两条曲线：

- 当 $R_{rx} > R_{tx}$（读快于写）：累计**接收**比特曲线在**发送**曲线之上，缓冲水位持续下降（风险：下溢 underflow）；
- 当 $R_{tx} > R_{rx}$（写快于读）：累计**发送**比特曲线在**接收**曲线之上，缓冲水位持续上升（风险：溢出 overflow）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">弹性缓冲区的尺寸估算（Slide 31）</span>

1. 名义上把缓冲保持在 $B/2$——新分组开始时允许缓冲填到 $B/2$，或确保新分组到来前缓冲已排到 $B/2$；
2. 缓冲大小要保证**在一个分组完成之前**既不溢出（overflow）也不下溢（underflow）；
3. 情形（$R_{tx} > R_{rx}$）：给定包间间隔（inter-packet gap），选取 $B/2$ 保证不溢出；
4. 情形（$R_{rx} > R_{tx}$）：给定最长分组，选取 $B/2$ 保证不下溢。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">防止溢出（Preventing overflow，Slide 32）</span>

图示：最长分组 $P_{max}$、包间间隔（inter-packet gap）、速率上界 $R_{max}$ 与下界 $R_{min}$ 下的累计比特曲线，缓冲半容量 $B/2$ 对应的时间窗口 $P_{max}/R_{max}$。

最坏情形：分组以最快速率 $R_{max}$ 写入、同时只以最慢速率 $R_{min}$ 被读走，发送时长为 $P_{max}/R_{max}$，期间缓冲最多盈余：

```math
\frac{P_{max}}{R_{max}}\cdot\left(R_{max}-R_{min}\right) \;\leq\; \frac{B}{2}
```

（原文此页中间推导步骤乱码严重，无法逐行复原；最终要求式为 $\dfrac{R_{max}-R_{min}}{R_{max}}\cdot P_{max} \leq \dfrac{B}{2}$，与下页例题数值自洽，见脚注。）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">防止下溢（Preventing underflow，Slide 33）</span>

对称的情形：分组以最慢速率写入、以最快速率被读走时缓冲被抽空。图示同样给出 $R_{max}/R_{min}$ 两条曲线与 $B/2$、$P_{max}/R_{max}$、包间间隔的时间标注。结论形式与上页对称（原文公式碎裂，见脚注）：速率偏差比例乘以最长分组，即为半缓冲容量 $B/2$ 的下界。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">弹性缓冲区尺寸估算：例题（Slide 34）</span>

- 最大分组 4500 字节；时钟容差 ±100 ppm（即最坏偏差比例 $\dfrac{R_{max}-R_{min}}{R_{max}} = 200 \times 10^{-6}$）；

```math
B \;\geq\; 2 \times \left(4500 \times 8 \times 200 \times 10^{-6}\right) = 14\ \text{bits}
```

因此：

1. 弹性缓冲区至少需要 14 bits；
2. 排空缓冲前至少等待 7 bits（$B/2$）；
3. 包间间隔至少 7 bits。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 弹性缓冲区这一段是"用确定性推理给硬件定参数"的完整范本，思路与你在 CSAPP 里见过的生产者-消费者缓冲完全同构：写时钟与读时钟各偏 ±100 ppm，最坏相对偏差 200 ppm，一个 36000 比特（4500 字节）的最长分组期间水位最多漂移 $36000 \times 200\times10^{-6} = 7.2$ 比特，所以半缓冲 $B/2 \geq 7.2$、整缓冲 $B \geq 14.4$，工程取 14——数字对得上，说明这套最坏情况推理自洽。注意三个设计选择的联系："缓冲名义保持 $B/2$"给两个方向的漂移各留一半余量；"包间间隔 ≥ 7 bits"给缓冲留出回到名义水位的恢复时间；"7 bits 后再排空"则是对偶的保护——这是利特尔法则（Little's law，利特尔法则）式的算账：$B/2 = (R_{max}-R_{min})\cdot T_{worst}$，只是这里时延窗口取的是分组发送时长而非到达间隔。曼彻斯特与 4b/5b 的对比同样值得记：曼彻斯特每比特 2 次电平保证时钟但浪费一半带宽，4b/5b 用 25% 开销换"足够多但不保证每比特"的跳变——一个把可靠性做到极致、一个把效率做到够用，这种权衡后来在 64b/66b（万兆以太网）、PCIe 的编码里被一再重演。
