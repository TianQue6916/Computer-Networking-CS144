### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 1：Unit 4: Congestion Control（单元开场白，Nick）</span>

**Nick**：在本单元中，你看到了传输层与分组交换（packet switching，分组交换）如何通过拥塞控制（congestion control，拥塞控制）相互作用。流量控制（flow control，流量控制）保证发送方发送的数据不超过接收方能接收的量，但两者之间通常隔着许多路由器（router，路由器），每台路由器都有自己的随时间变化的队列。拥塞控制是端点控制自己发送速率的方式，以免把队列填满、过度拥塞网络。这降低了丢包率，使 TCP 这类协议更容易跑得快；也让网络运转良好——既用足链路容量，又不丢太多分组。

🎥 *CS144 教授在视频中解释: "流量控制是关于终点主机的，它确保源主机不会通过发送超过它可以接收的（数据）使目的地主机过载"*（字幕来源：066 - p65 4-11 Congestion Control.zh.srt）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 2：What You Learned: Principles（你学到了什么：原理）</span>

- 网络拥塞是什么、由什么引起、在路由器里会发生什么；
- 我们希望网络在拥塞时的行为：最大-最小公平（max-min fairness，最大-最小公平）；
- AIMD：加性增、乘性减（additive increase, multiplicative decrease，加性增乘性减）；
- 多条 AIMD 流的行为与 TCP 吞吐量方程（throughput equation，吞吐量方程）。

**Phil 的讲稿**：首先，Nick 讲解了网络拥塞的原理。他展示了路由器开始以快于发送能力的速率收到分组时会发生什么：如果拥塞是短命的，路由器可以把多出来的流量吸收进队列再慢慢排空；如果拥塞长到队列溢出，路由器就必须丢弃一些分组。Nick 引入了一种非常有价值的思考方式：**与其设计一个"怎么丢包"的方案，不如先想清楚你希望网络整体表现成什么样**。我们希望网络是公平的，并解释了那意味着什么——最大-最小公平：如果你无法在不减少某个更慢的流的速率的前提下增加某个流的速率，网络就是公平的。达成这个目标的途径有很多，今天的网络也有各种机制。我们聚焦其中之一：TCP 如何控制自己的发送速率。我们引入了 TCP 用的基本算法，称为加性增、乘性减（AIMD）：运转平稳时，TCP 每个 RTT 把在途字节数增加一个报文段；检测到丢包时，把在途字节数减半。我们用 TCP 锯齿图（sawtooth，锯齿图）考察了这种行为的样子：每条流各自呈锯齿，但在许多流共享的链路上，它们平均下来变成链路持续的高利用率。借助锯齿图，我们用简单的 AIMD 推导了 TCP 的吞吐量：如果假设网络以均匀的丢包率 $p$ 丢包，那么一条 TCP 流的吞吐量就是 $\sqrt{3/2}$ 乘以 $1/(RTT\sqrt{p})$。增大往返时延，吞吐量下降。这个方程做了大量简化假设，但实践证明它相当准确，是思考网络行为时非常有价值的工具。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> Phil 那句"先想清楚你希望网络表现成什么样，再去设计丢包方案"，值得当作本单元的方法论总纲。它其实是工程设计的通用次序颠倒术：不是从机制出发问"它能干什么"，而是从目标出发问"什么机制能达成它"——最大-最小公平是目标层，AIMD 是机制层，Tahoe/Reno 状态机是实现层，三层各自独立、又层层支撑，这几乎就是"分层（layering，分层）"思想在算法设计上的复刻。你看概率论里排队模型也这样分层：先说清"我们要什么（稳定条件 $\lambda < \mu$）"，再挑"用什么到达/服务过程建模"，最后才是公式。学会在头脑里把"目标—机制—实现"拆成三层，你读任何系统论文都能立刻定位作者的真实贡献落在哪一层——这个技能比记住 AIMD 公式本身值钱得多。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 3：What You Learned: Practice（你学到了什么：实践）</span>

- TCP Tahoe、Reno 与 New Reno；
- 拥塞窗口（congestion window，cwnd）；
- 慢启动（slow start，慢启动）与拥塞避免（congestion avoidance，拥塞避免）；
- RTT 估计（RTT estimation，RTT 估计）；
- 自时钟（self-clocking，自时钟）；
- 快速重传（fast retransmit，快速重传）、快速恢复（fast recovery，快速恢复）、拥塞窗口膨胀（congestion window inflation，拥塞窗口膨胀）。

**Nick 的讲稿**：接着你学到了 TCP 如何在实践中实现这些原理。Phil 给你讲了 1980 年代后期互联网如何因拥塞而崩溃、对 TCP 做了哪些沿用至今的修复。你学了三个版本的 TCP：TCP Tahoe、TCP Reno 与 TCP New Reno。我们覆盖的第一个重要思想是：TCP 端点维护一个拥塞窗口。一条 TCP 流可以在网络中有 $N$ 个未确认字节在途，其中 $N$ 是其流量控制窗口与拥塞控制窗口二者的最小值——既不发送快于对端能接收的，也不快于网络能处理的。你学了 TCP 如何用两个状态控制拥塞窗口的大小：慢启动与拥塞避免。慢启动让 TCP 快速找到接近正确的拥塞窗口值，而拥塞避免使用 AIMD；TCP 从慢启动起步，并在首次检测到（丢包）时转入拥塞避免。你学了 TCP 如何估计其连接的往返时延（RTT）：它需要这个估计来判断确认何时超时。通过同时跟踪"收到确认平均要多久"与**方差**，TCP 既避免不必要的重传，又不至于等太久。你学了 TCP 如何用一种叫"自时钟"的技术控制向网络注入分组的速率。你在看我展示 TCP 行为动画时第一次见到自时钟；Phil 然后带你走了几个例子。有了自时钟，TCP 只有在收到确认或发生超时时才把新分组放入网络——这对防止拥塞极有帮助，因为这意味着 TCP 只在"分组离开网络"时才把分组放进网络。最后，我们覆盖了 TCP Reno 与 TCP New Reno 增加的三项优化。快速重传让 TCP 在只丢一个分组时能继续前进：不必等超时，TCP 检测到对前一段的三个重复确认就重传——这表明 TCP 仍在收到后续段、只是没收到那一段。借助快速恢复，TCP Reno 在三个重复确认时不退回慢启动，只把拥塞窗口减半、留在拥塞避免。最后，TCP New Reno 增加了额外优化——窗口膨胀，使得三个重复确认不会让 TCP 在等待缺失段被确认时损失一整个 RTT 的传输量。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 4：What You Learned: Practice（续，两位教授的收尾）</span>

**Phil**：关于拥塞真正迷人的地方在于：它是随着互联网演化**被发现**的。当初没人真的预想过会发生这种事，也没想过该如何控制它。它是网络变得足够大、使用足够重之后的一种涌现行为（emergent behavior，涌现行为）。如今它是网络领域的基础概念，被视为构建高性能、健壮网络的关键。

**Nick**：现代版本的 TCP 比我们讲的要先进一些，但它们演化出来的新特性主要是为了应对快得多的网络。操作系统自带的 TCP 版本其算法内核是 TCP Reno 或 TCP New Reno，在其上叠加了应对高速网络的额外特性与运行模式。去看看 Linux 源码，你会在那里看到这些算法。

**Phil**：同样漂亮的是：这些细枝末节的算法背后，有扎实的概念基础与理论。一方面我们在谈 RTT 方差估计、快速恢复、自时钟；另一方面，我们同时在谈能够收敛到最大-最小公平的 AIMD 流。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> Nick 那句"去看看 Linux 源码，你会看到这些算法"是全单元最实在的作业，值得按 CSAPP 的方式真的去做：在内核源码树里，`net/ipv4/tcp_cong.c` 与 `tcp_input.c` 实现了本单元的状态机，`struct tcp_sock` 中的 `snd_cwnd`、`snd_ssthresh` 字段就是拥塞窗口与慢启动阈值——你会亲眼确认"cwnd 是内核 TCP sock 结构的一个字段，而非首部字段"这个贯穿本单元的区分。再往深处一层，Phil 把"实践"与"理论"并置的收尾揭示了这个学科的完整结构：方差估计、窗口膨胀这些工程技巧不是零散的补丁，而是"AIMD 收敛到最大-最小公平"这一理论在现实约束（噪声信号、单包丢失、状态机可实现性）下的逐一兑现。理论告诉你什么是好的稳态，工程告诉你如何从任何状态到达并留在那里——只学其一，你都看不懂互联网；两头都学，你才拥有它的全貌。
