# CS144: Introduction to Computer Networking（计算机网络导论，Stanford Fall 2019）

## <span style="color:#c0392b;">The Internet and IP: Recap（互联网与 IP：单元总结）</span>

### <span style="color:#c0392b;">Part 1 · Levis 的回顾（Phil）</span>

<span style="color:#2471a3;">**[section]**</span>

Levis：在这个单元里，你学习了互联网如何工作的一些基础知识：网页浏览和 Skype 这类应用如何工作、一个应用如何使用互联网、以及互联网的基本结构。你还学习了网络的一些基本架构原则。也许到现在你已经能分清我们俩谁是 Phil、谁是 Nick 了。

现在你已经完成了第一个单元，应当对这张互联网**四层模型（4-layer model）**的图非常熟悉了。你现在知道：互联网被分解为四个不同的层，这四层是什么，以及它们如何协同工作。但比"它如何工作"更重要的是：你应当理解**它为什么这样工作**，以及为什么分层对所有网络都是好主意——而不只是对互联网。

你已经看到，互联网把数据拆成叫做**分组（packet）**的小单元来工作。当你请求一个网页时，你的电脑向 Web 服务器发送一些分组；互联网决定这些小数据块如何到达正确的目的地——服务器回应的那些装着页面的分组，又是如何正确地找到回到你这里的路。

你已经学到两个架构原则——分层（layering）与分组（packets）——如何汇聚成第三个架构原则：**封装（encapsulation）**。封装让各层以干净、简单的方式使用分组，使每一层对分组的使用互不依赖。后续单元里我们还会讲更多架构原则。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> Levis 强调"比 how 更重要的是 why"，这个提醒值得在笔记里占一页。四层模型的"why"可以压缩成两条你已见过的论据：其一，关注点分离让每层独立演化（TCP 算法升级时浏览器毫发无损）；其二，封装让异构网络可以互通（任何链路层只要会送帧，就能承载 IP）。用你熟悉的话说，分层是软件工程里"接口与实现分离"在系统尺度上的复刻，CSAPP 全书贯穿的正是这个思想——从系统调用接口到虚拟内存抽象。而"分组"这个看似平凡的拆分，换来的是统计多路复用带来的链路共享效率与近乎无限的弹性。以后当你学到传输层（Unit 2 的 TCP 状态机、滑动窗口）时，会看到这套分层原则如何继续"兑现"：传输层只需要链路层提供"尽力而为（best-effort）"的分组投递，就能在其上造出可靠字节流（reliable byte stream）——造法本身又是一次"用低承诺组件拼出高保证系统"的架构练习。

### <span style="color:#c0392b;">Part 2 · McKeown 的回顾：本单元的四大主题（Nick）</span>

<span style="color:#2471a3;">**[section]**</span>

McKeown：本单元我们学了四个主题：

1. **应用如何使用互联网。** Levis 讲解了各类应用使用互联网的通用方式，并以 Skype、BitTorrent 和 Web 为具体例子。你学到：大多数应用想要的，是在两个或多个端点之间的一条**可靠的、双向的字节流（reliable, bidirectional byte stream）**上通信。

2. **互联网的结构。** 你学习了什么是四层模型、每一层的职责；也学习了为什么每次通过互联网发分组都要用到互联网协议（Internet Protocol, IP），以及为什么我们把 IP 称为互联网的"细腰（thin waist）"。

3. **互联网协议（IP）。** 因为 IP 太重要，我们花了好几个视频介绍 IP 为我们做什么、以及它如何工作。到目前为止我们聚焦于第 4 版（IPv4），因为它是当今使用最广的版本。你学习了 IP 地址、路由器如何查找 IP 地址等等。课程后面你会学到更新的版本 IPv6。

4. **基本架构思想与原则。** 你学习了网络的三个基本原则，它们都与我们理解互联网息息相关。第一个是**分组交换（packet switching）**——把数据拆成自包含的信息分组、并依据分组首部（header）里的信息逐跳（hop-by-hop）转发这种简单的方式。第二个是**分层（layering）**，前面已经提过。第三个是**封装（encapsulation）**——把在一层处理过的分组放进下一层数据之中的过程。它帮助在层级结构中清晰地分离每一层处理数据的关注点。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "细腰（thin waist）"这个比喻值得展开：互联网协议栈中间窄、两头宽——链路层之下是以太网、WiFi、5G、光纤等层出不穷的物理技术，应用层之上是 HTTP、视频会议、游戏等五花八门的程序，但夹在中间的 IP 只有一个。任何新链路技术只要能"送 IP 分组"，无需改动上层；任何新应用只要"发 IP 分组"，无需改动底层。这与 CSAPP 里"系统调用接口"的地位一模一样：上层应用与底层硬件各自疯狂演化，中间的窄接口岿然不动，成为整个生态的汇合点。至于第 1 点的"可靠双向字节流"，你在 CSAPP ch11 已经是它的用户了——socket 的 `read()`/`write()` 给你的就是它；Unit 2 起你将看到它的造法：序列号（sequence number）、确认（acknowledgment）、重传（retransmission）、定时器（timer）。到时你会体会到：互联网的精妙，一半藏在"各层只承诺最小服务、却层层加码"的配合里。

### <span style="color:#c0392b;">Part 3 · Levis 的结语（Phil）</span>

<span style="color:#2471a3;">**[section]**</span>

Levis：你现在应当已经很好地理解了互联网的基本结构和三个基本架构思想。你理解了像网页浏览器这样的应用如何工作，以及互联网如何在两台计算机之间投递分组。你以前大概听过 TCP/IP 这个词——现在你知道 TCP 是什么、IP 是什么，以及它们为什么相关。乍一看，这些也许像是粗粝、底层的细节。但事实证明，它们正是互联网这座大厦的**基石**。每年都有新的应用和互联网的新用途涌现，但它们全部使用你正在学习的这些基本原则，而且几乎所有应用都在使用 TCP/IP。从这些惊人稳定的基本原理出发学起，你掌握的知识将在 5G 无线网络、Web 3.0 和物联网（Internet of Things）时代到来之后依然重要。

而这正是令人兴奋之处。互联网及其能做的事在不断扩张和变化，但有一些核心思想与原则贯穿了所有这些演化始终。学会了它们，你不仅知道互联网和网络今天如何工作，也很可能知道它们 20 年后将如何工作。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "这些细节是基石而不是尘埃"——可以用一个反例来体会这句话：2016 年前后兴起的 QUIC 协议把可靠传输从内核搬进了用户态（HTTP/3 的底层），看似推倒重来，但它复用的依然是本单元的全部概念：分组、序列号、确认、流控与拥塞控制、基于 IP 的细腰；它改变的是**实现位置**，而非**架构原则**。换句话说，原则的寿命远长于任何具体协议的寿命——TCP/IP 从 1974 年的论文到今天支撑了半个世纪，而应用层浪淘沙般换了无数代。对学习者而言，最划算的投资策略就是押注这类"低频变化"的知识：数据结构之于算法岗、体系结构之于系统岗、本单元的分层与分组之于网络方向，都是同一类资产。CS144 这门课的编排正是有意如此：先给足"why"（架构原则），再给"how"（传输层、路由、拥塞控制的机制细节）——带着 why 去学 how，每一个机制你都会知道它是为了在哪个约束下交换掉哪种代价。
