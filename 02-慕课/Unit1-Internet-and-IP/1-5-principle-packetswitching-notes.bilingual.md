# CS144: Introduction to Computer Networking（计算机网络导论，Stanford Fall 2019）

## <span style="color:#2471a3;">**[lecture]**</span> <span style="color:#c0392b;">1-5 Packet Switching Principle（分组交换原理）</span>

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">开场：一个曾被视为革命性的想法</span>

**Phil：** 互联网被设计出来时，建立在一个备受争议、堪称革命性的想法之上：packet switching（分组交换）。如今它看起来理所当然，是搭建网络的显然方式，但过去并非如此。这是一个非常简单的想法——不过简单想法向来如此，一旦投入实践，就会涌现出许多有趣的推论。本课程将用一整周来讨论分组交换及其影响，而这段视频先呈现高层思想及其直接的好处。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Packet 与 packet switching 的定义（Nick）</span>

> <span style="color:#2471a3;">**[definition]**</span> <span style="color:#00838f;">**Packet（分组）：** 一个自包含（self-contained）的数据单位，携带了它到达目的地所需的全部信息。</span>

**Nick：** 分组交换的思想是：我们把数据切分成离散的、自包含的数据块。每个块叫做一个 packet，它携带足够的信息，使网络能够把它投递到目的地。假设有一个源（source）、一个目的地（destination），中间是 A、B、C 三台 packet switch（分组交换机）。当 A 收到一个发往目的地的 packet，就沿链路把它发给 B；B 收到后发给 C；C 收到后送给目的地。在最简形式的分组交换里，**<span style="color:#00838f;">每个 packet 被单独地、独立地路由。</span>** 比如假设 B 还连着另一台交换机 D：B 刚把一个 packet 发给 C，马上就可以把下一个 packet 发给 D；或者若下一个 packet 也发往同一目的地，它也可以背靠背地把两个 packet 都发给 C。

> <span style="color:#2471a3;">**[definition]**</span> <span style="color:#00838f;">**Packet switching（分组交换）：** 对每个到达的 packet 独立处理——为它挑选一条出链路（outgoing link）；链路空闲就发送，否则把 packet 留待稍后发送。</span>

举一个分组交换可以如何工作的例子：每个 packet 携带一条显式路由（explicit route），写明沿途每台分组交换机的 ID。我们称之为 "self routing" 或 "source routing"（源路由），因为路由是源指定的。源发送 packet 时，把 A、B、C、目的地放进包里，然后把包转发给 A；A 查看首部，发现下一跳是 B，就转发给 B；B 看到下一跳是 C；C 看到最后一跳是目的地。事实上互联网支持源路由，但通常被关闭，因为它引发严重的安全问题：路由器的拥有者不想让你告诉他们怎么发 packet，因为你可能诱骗他们把包发到不该去的地方——比如一些安全的计算机。

一个简单的优化——也是今天互联网主要采用的做法——是在每台交换机里放置少量状态（state），告诉它 packet 该发往哪个 next hop（下一跳）。例如，交换机可以有一张"目的地址 → 下一跳"的表；收到 packet 时查表，把包发往相应下一跳。在这个模型里，packet 只需携带目的地址。凭这个地址，沿途每台交换机都能做出正确决定。比如在我们这张网络图里，A 的表写着"发往目的地的包 → 交换机 B"，B 的表写着"→ C"，依此类推。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">没有专用电路：header、转发表与逐跳转发</span>

在分组交换中，不存在承载我们数据的 dedicated circuit（专用电路）。我们改为：给一块数据加上 header（首部），称之为一个 packet。首部包含这个包要去哪里的地址——就像信封告诉邮局把信寄到哪里。分组交换网络由 end-hosts（终端主机）、links（链路）和 packet switches（分组交换机）组成。我们发送 packet 时，它被逐跳（hop-by-hop）路由到目的地：每台交换机在自己的 forwarding table（转发表）里查找 packet 首部中的地址。例如，这个包发往 B；我们发送它时，第一台路由器在本地表里查地址 B，发现下一跳是交换机 S2；S2 和 S4 照做，最终包被投递到 B。互联网里有几种不同类型的分组交换机：有的叫做 router 或 gateway（网关），有的叫做 Ethernet switch（以太网交换机）。它们各自我们后面都会学到；现阶段你只需知道：它们都是分组交换机，都依据首部中的目的地址转发 packet。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 🎥 *McKeown 在视频中解释： "而且互联网今天主要做的事情是将一小部分状态放在每个交换机中"*（字幕来源：006 - p5 1-5 Packet switching principle.zh.srt）。source routing（源路由）被禁用的理由值得展开，因为它示范了"能力即攻击面"的安全直觉：源路由把"选路权"从网络移交给了发送方，攻击者于是可以指定路径，让 packet 绕经自己控制的路由器（流量劫持），或把包瞄准本不该抵达的内网机器（绕过边界防护）。把选路权收回给沿途的交换机——每个包只带目的地址、交换机查自己的表——等价于把"完整路径知识"分散成 $N$ 个"单跳局部知识"，这正是互联网扩展到数十亿设备的根本原因之一：任何一台路由器只需知道"下一跳往哪走"，而不必知道全网的拓扑。这与 6.042J 里最短路问题的一个实现要点暗合：Dijkstra 算法计算最短路后，每个节点只需记录 predecessor（前驱）信息即可重建路径——全局最优性可由局部决策拼接而成。Bellman-Ford 距离向量路由协议（后续章节会讲）正是把这一点做到极致：路由器间只交换邻居距离，逐跳收敛出全局最短路。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">分组交换的两大好处（Phil）</span>

**Phil：**（原文按语：这一部分似乎非常基于电路交换网络。许多学生从没用过电路网络。为什么需要 per-flow state（按流状态）？为什么可能无法高效共享链路？）

分组交换有两个非常好的性质。**其一：交换机可以对每个 packet 做单独的、本地的决策。** 它不需要为"见过的包"或"两个包是否同往一个目的地"保存额外状态。即使许多 packet 同属某个更大的传输或协议，交换机也无须知情或关心。交换机不需要知道哪些包属于一个 Skype 通话、哪些是一个 Web 请求、哪些又是你计算机的固件更新——它只管转发 packet。这极大简化了交换机。

**其二：它让交换机能把一条链路高效地在多方之间共享。** 比如，考虑一个家庭无线路由器，两个人各自用笔记本电脑上网：一个人在读网页时，另一个人可以以链路的全部速度下载文件；第一个人开始加载新网页时，链路就在两人之间共享；下载完成后，第一个人又能用上全部速度。这两点都非常重要，所以我们再分别展开讲讲。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Flow（流）与"无需 per-flow 状态"的四重好处（Nick）</span>

**Nick：** 当然，我们通信时通常不止发一个 packet，而是发许多——例如一次语音通话由许多连续的、同属一次通信的 packet 构成。我们把这个 packet 序列称为一个 flow（流）。更正式地：

> <span style="color:#2471a3;">**[definition]**</span> <span style="color:#00838f;">**Flow（流）：** 属于同一次端到端通信的 datagram（数据报）的集合，例如一条 TCP 连接。</span>

先看"每个 packet 独立路由"这一点。因为每个 packet 自包含，交换机不需要了解 packet 的分组情况或流。想象一下，如果每台交换机都必须跟踪穿过它的每一条 Web 连接——那需要维护的海量状态将难以管理！相反，把每个 packet 独立对待，交换机的建造、管理和排障都简单得多。

具体有四重好处：

- **无需增删状态。** 想象一下，你每加载一个网页，都得与沿途每台交换机通信、为你的请求建立状态——这会让一切慢得多。而现在你只管发包，交换机自会恰当转发。
- **无需存储状态。** 交换机必须快，状态就得存在非常快的存储器里——那很贵。免掉状态，交换机就能专注做好一件事：快速转发 packet。
- **无需处理失效清理。** 想象你发起一个 Web 请求后平板电脑没电关机了：交换机上还留着这个请求的 per-flow state。如果创建状态的某个节点失效了，交换机就得知道如何善后——否则你会得到上百万、上十亿的死流（dead flows）吃光内存。而分组交换中交换机没有任何 per-endpoint state（按端点状态）：你的平板死了，交换机毫不在意，只是不再收到它发的 packet 而已。这样，交换机在功能上就更独立于那些借道它的计算机。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 🎥 *Nick McKeown 在视频中解释： "你需要与路径上的每个交换机通信，只是为设置状态"*（字幕来源：006 - p5 1-5 Packet switching principle.zh.srt）。这一节用四重好处论证的其实是同一个命题：**状态（state）是分布式系统里最贵的资源**。把镜头拉远看，这正是电路交换（circuit switching，如传统电话网）与分组交换的分水岭：电路交换在通话开始时要在沿途每台交换机"预订"一段资源并写下状态，通话结束再逐台拆除——建立/拆除本身就是开销，节点失效还会留下"幽灵电路"。而分组交换把状态从网络抽干：交换机只见 packet 不见 flow，于是故障恢复退化为"什么都不用做"。你可以用 CSAPP 里进程与文件描述符的对比来体会：内核为每个打开的连接维护状态，文件描述符泄漏的后果你已经吃过；互联网的设计者选择让"转发面"零连接状态，把状态全部上移到端系统（TCP 连接状态属于两端主机，不属于路由器）。附带一个工程视角：无状态转发面还是后来 SDN（软件定义网络）能"控制面与数据面分离"的先决条件——正因为交换机够笨，控制逻辑才能被整体抽走重构。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">突发流量与 statistical multiplexing（统计多路复用）</span>

**Phil：** 想想你平时怎么用互联网——你的使用是 bursty（突发的）：加载一个网页，然后阅读，然后加载下一个；从 iTunes 下载几首歌，然后去听；看 45 分钟的 Netflix，然后停下。数据流量是突发的：它并非总以固定速率收发数据，而是随时间跳升与跌落、起起伏伏。

虽然有大规模的流量变化与峰值——下午 3 点和晚上 8 点通常是高峰，凌晨 2 点是低谷——但在更小的尺度上，流量非常突发，而且这些 burst（突发）往往是相互独立的。比如你和你的朋友在咖啡馆里各自浏览网页：你加载新页面与你朋友加载新页面基本相互独立；有时会重叠，但常常错开。把你们的流量都当作"一堆 packet"来对待，无线路由器就能非常有效且简单地在你俩之间共享它的容量：你在加载页面而朋友在阅读时，路由器可以把全部容量都给你的 packet；反过来也一样；你俩同时加载页面时，链路就在你们之间分享。**<span style="color:#00838f;">把一份资源以概率的或统计的方式在多个用户之间共享，这个思想叫做 statistical multiplexing（统计多路复用）。</span>** 说它"统计"，是因为每个用户获得的份额取决于其他人正在使用多少资源：朋友在阅读时，你可以用满整条链路；两人同时加载页面，你获得一半容量。

**Nick：** 以上就是分组交换的两大好处：其一，交换机因为不需要了解 packet 流而变得简单；其二，它让我们能在共享一条链路的许多流之间高效地分配容量。这个简单的构件在当时是革命性的，如今已被公认为搭建网络的标准方式。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 🎥 *Nick McKeown 在视频中解释： "并且每个用户根据其他人如何使用资源获取到一个统计份额"*（字幕来源：006 - p5 1-5 Packet switching principle.zh.srt）。统计多路复用是这门课里你概率论工具箱第一次大规模上场的地方，值得把模型搭出来。设链路容量为 $C$，每个用户独立地以概率 $p$ 处于"活跃发包"状态（这实质是一个伯努利模型；连续时间版本对应泊松过程），则同时活跃的用户数服从二项分布，其期望 $E[X] = np$。工程上的核心不等式是：只要 $C \ge np + \text{波动余量}$，链路就能以高概率服务所有活跃用户。妙处在于：若按"每个用户的峰值需求之和"（电路交换思路）预留容量，代价是 $n \times \text{峰值}$，而统计复用只需约 $np$——用户越多、独立性越强，相对节省越惊人，这正是大数定律的工程变现：**大量独立突发叠加后的总流量，其相对波动（标准差/期望）随 $n$ 增大而缩小**，资源可以按"平均"而非"最坏"来供给。代价当然也存在：当活跃数超出容量时排队时延上升、超出缓冲区则丢包——这个"收益与拥塞共存"的权衡，正是课程第三章排队论与后面拥塞控制章节的伏笔。你学 Bertsekas 概率论时遇到的 M/M/1 排队系统，将来会精确刻画这一节只能定性描述的现象。
