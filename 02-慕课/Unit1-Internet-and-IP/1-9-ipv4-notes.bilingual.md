# CS144: Introduction to Computer Networking（计算机网络导论，Stanford Fall 2019）

## <span style="color:#c0392b;">Names and Addresses: IPv4（名字与地址：IPv4）</span>

### <span style="color:#c0392b;">Slide 1 · Names and Addresses: IPv4（名字与地址：IPv4）</span>

<span style="color:#2471a3;">**[section]**</span>

互联网协议（Internet Protocol, IP）让两台计算机能够在一个由许多不同链路层（link layer）构成的网络之上交换消息。它依靠**地址（address）**来做到这一点。每个 IP 分组都有源地址（source address）和目的地址（destination address）。路由器（router）根据分组的目的地址来决定把它转发到哪条链路（link）上。我们来仔细看看 IPv4 地址长什么样、如何格式化、以及如何分配。

### <span style="color:#c0392b;">Slide 2 · Goal of Internet Protocol Addresses（IP 地址的目标）</span>

<span style="color:#2471a3;">**[section]**</span>

- 把许多不同的网络"缝合"在一起
- 需要一种与具体网络无关的、唯一的地址

互联网协议最初的目标是把许多不同的网络拼接成一个整体。要做到这一点，协议需要一种指代计算机的方式：既独立于计算机所在的网络，又是全局唯一的。这样，一台连在 IBM 网络上的计算机与一台通过串行线（serial line）接到路由器的计算机才能互相通信、互相寻址。如今 IPv4 地址要更复杂一些——由于诸多特例和特殊用途，它们并非严格唯一——但现在我们先假设它们唯一。

### <span style="color:#c0392b;">Slide 3 · Internet Protocol, Version 4（互联网协议第 4 版：地址与掩码）</span>

<span style="color:#2471a3;">**[section]**</span>

- <span style="color:#00838f;">**一个 IPv4 地址标识互联网上的一台设备**</span>
  - 第 3 层（网络层）地址
- 32 位长（4 个八位组/octet）：形如 a.b.c.d
  - 例：171.64.64.64
  - 例：128.30.76.82
  - 例：12.22.58.30
- **子网掩码（netmask）**：应用这个掩码，若匹配，则在同一网络
  - 掩码 255.255.255.0 表示前 24 位匹配
  - 掩码 255.255.252.0 表示前 22 位匹配
  - 掩码 255.128.0.0 表示前 9 位匹配
  - 掩码越小（1 越少），网络越大

IPv4 地址长 32 位，通常写成 4 个**八位组（octet）**——4 个 8 位值——形如 a.b.c.d。例如 171.64.64.64、128.30.76.82、12.22.58.30。每个通过 IPv4 接入的设备都有一个 IP 地址；IP 层把目的地址是它的分组送到该设备。

除地址外，设备通常还有一个**子网掩码（netmask）**。掩码告诉设备哪些 IP 地址是本地的——在同一条链路上——哪些则需要经过 IP 路由器（router）。想象一台接在无线网络里的笔记本：要向同一无线网络中的另一台设备发分组，它不需要经过 IP 路由器——理论上可以直接把分组发给对方，因为它们在同一条链路上。

掩码写成从最高有效位开始的一串连续的 1。例如掩码 255.255.255.0 意味着前 3 个八位组全为 1（$2^8 - 1 = 255$），最后一个八位组为 0。也就是说：凡是与你的地址的前三个八位组——24 位——都相同的 IP 地址，就在同一个网络里。掩码 255.255.252.0 表示掩码长 22 位，而 255.128.0.0 是 9 位的掩码。

判断两台计算机是否在同一网络的方法是：把两个地址分别与掩码做**按位与（bitwise AND）**。如果结果相等，它们就在同一网络。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 掩码的本质用 6.042J 的语言说最清楚：它定义了 IP 地址集合上的一个**等价关系（equivalence relation）**——"与我的地址按位与掩码后结果相同"。自反、对称、传递都显然成立，而每个等价类恰好是一个 CIDR 前缀块，所有等价类构成对整个地址空间的一个**划分（partition）**。所以"判断两台机器是否同网"本质是在问"这两个元素是否在同一等价类"，而按位与就是一次 $O(1)$ 的类成员测试——没有比较循环、没有查表，一条 AND 指令完成。从第一性原理看，这也是一个漂亮的工程权衡：32 位地址空间太大了，不可能为每对主机维护"直连/绕行"信息；用"前缀相同的归为一类"这个规则，把全局唯一性分解成"类内直连、类间走路由器"的两级结构，与 CSAPP ch9 中虚拟内存"页（page）划分 + 页表"的思想同构——都是用固定粒度的等价类来压缩管理开销。记住 255 = $2^8-1$（八位全 1），后面读掩码会非常快。

### <span style="color:#c0392b;">Slide 5 · Quiz（随堂测验）</span>

<span style="color:#2471a3;">**[exercise]**</span>（习题保持英文原文）

Quiz
For each source, destination, and netmask, mark whether the destination is in the same network as the source.

| Source | Destination | Netmask | Same Network? |
|---|---|---|---|
| 128.34.1.15 | 128.35.1.15 | 255.255.0.0 |  |
| 10.0.1.4 | 10.0.1.5 | 255.255.255.0 |  |
| 10.0.1.4 | 10.0.2.5 | 255.255.255.0 |  |
| 171.64.15.33 | 171.64.15.5 | 255.255.255.224 |  |
| 171.64.15.33 | 171.19.201.2 | 255.0.0.0 |  |

<span style="color:#2471a3;">**[solution]**</span>

> 这是一道随堂测验。对每组源地址、目的地址与掩码，判断目的地址是否与源地址在同一网络。
>
> - 第一行的答案是**否**：它们在不同的网络。两个地址在第二个八位组上不同——34 对 35。把两个地址与掩码做按位与，分别得到 128.34.0.0 和 128.35.0.0，不相等。
> - 第二行的答案是**是**：同一网络。按位与后两者都得到 10.0.1.0。
> - 第三行的答案是**否**：不同网络，因为它们在第三个八位组上不同。源地址在网络 10.0.1.0，而目的地址在网络 10.0.2.0。
> - 第四行的答案是**否**：不同网络。只需看最后一个字节：左边地址的 33 是 $0\text{x}21$，右边地址的 5 是 $0\text{x}05$；而 224 是 $0\text{x}\text{E}0$，即最高 3 位为 1。源地址这 3 位已置位而目的地址没有，所以不匹配。与掩码按位与后，源地址是 171.64.15.32，目的地址是 171.64.15.0。
> - 最后一行的答案是**是**：它们在第一个字节上匹配——与掩码按位与后都是 171.0.0.0。

### <span style="color:#c0392b;">Slide 6 · Address Structure (historical)（地址结构：历史上的分类制）</span>

<span style="color:#2471a3;">**[section]**</span>

- 最初是分层的（hierarchical）：网络 + 主机
  - 网络（network）部分：找到正确的网络（管理域/administrative domain）
  - 主机（host）部分：在网络内找到正确的设备（管理域之内）
- 最初分三类地址：A 类（class A）、B 类（class B）、C 类（class C）

图示：三类地址的位分布——A 类以 0 开头，后接 7 位网络号与 24 位主机号；B 类以 10 开头，后接 14 位网络号与 16 位主机号；C 类以 110 开头，后接 21 位网络号与 8 位主机号。

那么 IP 地址是如何分配的呢？最初它们被划成三类：A 类、B 类、C 类。每一类把 IP 地址分成两部分：网络与主机。地址的网络部分表示一个管理域（administrative domain），如 MIT、BBN 或 Stanford；主机部分表示该网络内的哪台设备。A 类地址以 0 开头，有 7 位网络号（即 128 个网络）和 24 位主机号，可覆盖 1600 万台计算机。B 类地址有 16 位主机号，可覆盖 65,536 台计算机。C 类地址有 8 位主机号，可覆盖 256 台计算机。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 🎥 *McKeown/Levis 在视频中解释: "无论是 MIT 还是斯坦福，都收到了第一个类 A 地址之一……有一段时间，MIT 将为其宿舍分配相当于类 B 的地址，最多为几百人分配 65,536 个地址。"*（字幕来源：016 - p15 1-9d IPv4 addresses.zh.srt）分类制（classful addressing）的失败提供了一个极好的"粒度错配"案例：地址类别只有 8、16、24 位三种网络前缀可选，相当于把地址空间的切分粒度硬编码成了三档。一个只有几百人的 MIT 宿舍按"最接近的档位"领到一个 B 类——65,536 个地址，利用率不到 1%。这正是"资源不是不够用，而是被粗粒度的分配方式浪费掉"的活教材。1993 年的 CIDR（见下一节）把这三档打散成任意长度前缀，等价于把"离散三档"换成"按位可调的连续档位"，才让 32 位地址空间又续命了几十年。注意本讲强调的另一个词：**分层（hierarchical）**——网络号在前、主机号在后，使得"先找到网络、再在网络内找到设备"成为可能，这与 DNS 域名从右往左逐级解析的分层逻辑是同一个设计思想：层级化让每一级只需要局部知识。

### <span style="color:#c0392b;">Slide 7 · Address Structure Today（今天的地址结构：CIDR）</span>

<span style="color:#2471a3;">**[section]**</span>

- 仍然把连续的地址区间分配给邻近的网络
  - A、B、C 类太粗（例如 MIT 的宿舍！）
  - 参见 http://news.stanford.edu/news/1999/january27/itss127.html
- **无类别域间路由（Classless Inter-Domain Routing, CIDR）**
  - 地址块是一个数对：地址,数量（address, count）
  - 数量是 2 的幂，指定掩码长度
  - 171.64.0.0/16 表示 171.64.0.0 至 171.64.255.255 范围内的任意地址
  - 一个 /24 描述 256 个地址，一个 /20 描述 4,096 个地址
- Stanford 今天拥有 5 个 /16 块——约 325,000 个地址

A、B、C 类虽然简单，但人们很快发现它们不够灵活。例如 MIT 和 Stanford 都拿到了最早的一批 A 类地址块——超过 400 万个地址。有一段时间，MIT 给每个宿舍分配相当于一个 B 类的地址——几百人用 65,000 个地址！在 IP 地址充裕的年代这不算问题，但随着使用量增长，我们需要更好的分配策略。

一个有用的注脚：Stanford 在 1999 年交还了它的 A 类地址块，而 MIT 至今仍保留着自己的。

如今 IPv4 地址通过 **CIDR（Classless Inter-Domain Routing，无类别域间路由）**来组织。前缀不再只能是 8、16、24 位，CIDR 允许前缀是任意位数。这意味着所有 CIDR 前缀定义的地址块大小都是 2 的幂。谈论 CIDR 地址时，我们说的是它的掩码长度。例如，说"slash 16"（/16）就是指长度为 16 的掩码，这个 CIDR 块描述 $2^{16}$ 个地址，即 65,536 个；说"slash 20"（/20）就是指长度为 20 的掩码，这个 CIDR 块描述 $2^{12}$ 个地址，即 4,096 个。CIDR 块就是如今地址被组织、编址和管理的方式。

Stanford 今天拥有 5 个 /16 块，约 325,000 个 IPv4 地址。

### <span style="color:#c0392b;">Slide 8 · IPv4 Address Assignment（IPv4 地址的分配）</span>

<span style="color:#2471a3;">**[section]**</span>

- **IANA**：互联网号码分配局（Internet Assigned Numbers Authority）
  - 隶属于互联网名称与数字地址分配机构（Internet Corporation for Assignment of Names and Numbers, ICANN）
- IANA 向区域性互联网注册机构（Regional Internet Registry, RIR）发放 /8
  - 2011 年 2 月用尽，处于其章程的特殊收尾条款：给每个 RIR 各发 1 个 /8
- 每个 RIR 负责一个地理区域，各有自己的分配政策
  - AfriNIC：非洲
  - ARIN：美国、加拿大、加勒比地区、南极洲
  - APNIC：亚洲、澳大利亚、新西兰
  - LACNIC：拉丁美洲、加勒比地区
  - RIPE NCC：欧洲、俄罗斯、中东、中亚

那么 IPv4 地址究竟是如何分配和管理的？有一个组织叫 IANA（互联网号码分配局）。最终权威是 ICANN（互联网名称与数字地址分配机构），由 ICANN 把工作委派给 IANA。

IANA 把 /8 块（每个描述 1600 万个地址）发放给区域性互联网注册机构（RIR）。每个大洲有自己的 RIR：美国的 RIR 是 ARIN，西太平洋的是 APNIC。这些 RIR 各有政策，决定如何把 /8 拆成更小的地址块，分配给需要的各方。

你可能在新闻里读到过"IP 地址用完了"。这并不完全属实——今天仍有许多未被使用的地址。真正发生的事情是：IANA 没有可以发放的 /8 了。它走到了章程里一个特殊的收尾条款：当只剩下最后 5 个 /8 时，IANA 给每个 RIR 各发一个 /8。如今地址的管理与分配由各 RIR 负责。2012 年，时任互联网架构委员会（Internet Architecture Board, IAB）成员的 Jon Peterson 在 Stanford 就此引发的政治、经济与技术问题做过一场报告。这不是本课程的必读材料，但我非常推荐。

至此你已看到 IPv4 地址的结构、分配方式，以及终端主机如何做它的第一跳路由决策——即发往本地节点还是网关路由器（gateway router）。如今地址以 CIDR 块为单位管理和分配，块的大小由前缀长度定义：前缀越短（如 /8），块越大；前缀越长（如 /10），块越小。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> IANA → RIR → ISP → 用户的四级分配结构，本质是一个"权威逐级下放"的分层系统，与 DNS 从根服务器到本地解析器的层级、以及 CIDR 本身"网络号 → 主机号"的层级互为镜像：互联网的地址、名字、路由全部采用同一套"分而治之"的管理哲学——顶层权威只管粗粒度，细节交给下级。2011 年 2 月"IANA 发完最后一个 /8"是个值得记住的里程碑：IPv4 只有 $2^{32}$ 个地址，约 43 亿，而全球联网设备早已数倍于此。这个"地址不够"的压力正是两件事的直接推手：其一是 NAT（网络地址转换，让多台机器共享一个公网地址，Unit 5 会讲）；其二是 IPv6 把地址从 32 位扩到 128 位——$2^{128}$ 是一个天文数字。学习建议：把"前缀长度"和"地址稀缺"这两个线索串起来，你就能理解为什么路由表聚合（把相邻小块合成大块以缩小转发表）成为可能，这正铺向下一讲的**最长前缀匹配（longest prefix match）**。
