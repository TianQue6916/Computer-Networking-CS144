# CS144: Introduction to Computer Networking（计算机网络导论，Stanford Fall 2019）

## <span style="color:#c0392b;">Longest Prefix Match（最长前缀匹配）</span>

### <span style="color:#c0392b;">Slide 1 · Longest Prefix Match（最长前缀匹配）</span>

<span style="color:#2471a3;">**[section]**</span>

互联网路由器（router）可以拥有许多条链路（link）。对一个收到的分组（packet），它们有许多可选的转发方向。如今的路由器通常使用一种叫做**最长前缀匹配（Longest Prefix Match, LPM）**的算法，来选择用哪条链路转发分组。

### <span style="color:#c0392b;">Slide 2 · Inside the Stream（数据流之中）</span>

<span style="color:#2471a3;">**[section]**</span>

图示：客户端（Client）与服务器（Server）之间隔着若干台路由器（Routers）。客户端一端标注：IP 地址 171.67.76.157、TCP 端口（port）23946；服务器一端标注：IP 地址 128.148.252.129、TCP 端口 80。

在这个例子里，客户端想与服务器在 80 端口（Web 服务器的典型端口）上建立 TCP 连接。建立连接和传输数据的分组要在客户端与服务器之间经过许多跳（hop）。每一跳上，每台路由器都要决定把这个分组从哪条链路转发出去。

### <span style="color:#c0392b;">Slide 3 · Inside Each Hop（每一跳的内部）</span>

<span style="color:#2471a3;">**[section]**</span>

图示：右侧展示一张转发表（forwarding table），路由器当前处理的分组目的地址标注为 216.239.47.186。表中 x 表示通配符（wildcard）：

| dest（目的） | link（链路） |
|---|---|
| default（默认） | 1 |
| 171.33.x.x | 5 |
| 23.x.x.x | 2 |
| 28.33.5.x | 4 |
| 171.32.x.x | 2 |
| 67.x.x.x | 6 |
| 216.x.x.x | 1 |

路由器如何做这个决定？它依靠所谓的**转发表（forwarding table）**，即右图所示。转发表由一组"部分 IP 地址"构成——那些 x 表示地址是不完整的，x 是通配符。例如第二行条目 171.33.x.x 的意思是"任何第一字节为 171、第二字节为 33 的 IP 地址"，它同时涵盖 171.33.5.245 和 171.33.1.1 这样的地址。

分组到达时，路由器检查哪条转发表条目**最好地**匹配这个分组，然后把分组从与该条目关联的链路转发出去。这里说的"最好"，指的是**最具体（most specific）**。默认路由（default route）实际上就是全部通配符——它匹配每一个 IP 地址。如果一个分组到达时，没有比默认路由更具体的路由，路由器就使用默认路由。

### <span style="color:#c0392b;">Slide 4 · Longest Prefix Match（最长前缀匹配）</span>

<span style="color:#2471a3;">**[section]**</span>

- IP 路由器用来从转发表中选择匹配条目的算法
- 转发表是一组 CIDR 条目
  - 一个地址可能匹配多个条目
  - 例如：171.33.0.1 同时匹配右边的两条
- <span style="color:#00838f;">**算法：使用匹配前缀最长的转发表条目**</span>
  - 对 171.33.0.1，最长前缀匹配会选择链路 5

图示：一张只有两条目的条目的转发表——0.0.0.0/0 对应链路 1，171.33.0.0/16 对应链路 5。

最长前缀匹配（LPM）就是 IP 路由器用来决定如何转发分组的算法。每台路由器都有一张转发表，表中的条目分两部分：一个描述地址块的 CIDR 条目，以及匹配该 CIDR 条目的分组应走的下一跳（next hop）。一个地址可能同时属于多个 CIDR 条目。

例如右表中只有两条：一条是前缀长度为 0 的默认路由，另一条是 171.33.0.0/16。默认情况下，所有分组都走链路 1。但如果分组目的地址的前 16 位——两个八位组——匹配 171.33，路由器就会把它送上链路 5。因为 16 位的前缀比 0 位的前缀更长，也就更具体。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 请务必把**转发（forwarding）**与**路由（routing）**分开：你在 6.042J/CLRS 里学的 Dijkstra、Bellman-Ford 属于后者——它们在图上跑最短路，算出"从本路由器到每个目的网段应当走哪条边"，并把结果**填进**转发表；而 LPM 属于前者，是数据平面上一台路由器拿到具体分组后的本地查表动作，不涉及任何图搜索。这两层的关系可以精确对应到 CLRS 的"预计算 + 查询"模式：Dijkstra 是一次性的预计算（控制平面，慢），LPM 是每个分组都要做的高频查询（数据平面，必须极快——骨干路由器每秒要处理千万级分组）。查询的数据结构也有讲究：CIDR 前缀本质是"以位为字符的前缀串"，所以工业界用 **trie（前缀树/字典树）**变体（如 PATRICIA、压缩 trie）来组织，查询时间正比于地址长度 32 而非表项数 N——这正呼应 CLRS 中"比较排序下界 $\Omega(n\log n)$，而利用键的结构（如基数排序/trie）可以突破"的思想。最长前缀优先的规则则保证了"越具体的路由越优先"，与操作系统路由表中 /32 主机路由压过 /8 网段路由是同一条规则。

### <span style="color:#c0392b;">Slide 7 · Quiz（随堂测验）</span>

<span style="color:#2471a3;">**[exercise]**</span>（习题保持英文原文）

Quiz
With the forwarding table on the right, over which link will a router using longest prefix match send packets with the following IP destination address?

| dest | link |
|---|---|
| 0.0.0.0/0 | 1 |
| 18.0.0.0/8 | 5 |
| 171.0.0.0/8 | 2 |
| 171.0.0.0/10 | 4 |
| 171.0.15.0/24 | 1 |
| 55.128.0.0/10 | 6 |
| 63.19.5.0/30 | 3 |

A. 63.19.5.3  B. 171.15.15.0  C. 63.19.5.32  D. 44.199.230.1  E. 171.128.16.0

<span style="color:#2471a3;">**[solution]**</span>

> 使用右侧的转发表，采用最长前缀匹配的路由器会把目的地址为下列 IP 的分组从哪条链路发出？
>
> - **A. 63.19.5.3 → 链路 3。** 63.19.5.3 匹配两个前缀：默认路由和前缀 63.19.5.0/30。该前缀长 30 位，而 63.19.5.3 只有最后两位与它不同。/30 比 /0 更长，所以路由器选择链路 3。
> - **B. 171.15.15.0 → 链路 4。** 171.15.15.0 匹配三个条目：默认路由、171.0.0.0/8 和 171.0.0.0/10。它不匹配 171.0.15.0/24，因为它的第二个八位组是 15 而不是 0。第三个匹配 171.0.0.0/10 是最长前缀，所以路由器把分组送上链路 4。
> - **C. 63.19.5.32 → 链路 1。** 最长前缀匹配是默认路由。它不匹配 63.19.5.0/30，因为它的第 26 位不同。
> - **D. 44.199.230.1 → 链路 1。** 最长前缀匹配是默认路由。
> - **E. 171.128.16.0 → 链路 2。** 该地址匹配两个前缀：默认路由和 171.0.0.0/8。它不匹配 171.0.0.0/10，因为它与该前缀在第 9 位上不同。171.0.0.0/8 是最长前缀，所以路由器把分组从链路 2 转发出去。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 🎥 *McKeown/Levis 在视频中解释: "六十三一九五三的答案是链接三。六十三一九五三匹配两个前缀：默认路由和前缀六十三一九五零，前缀长度为三十位。"*（字幕来源：019 - p18 1-10c Longest prefix match (LPM).zh.srt）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这五道题值得逐个复盘，因为它们恰好覆盖了 LPM 的全部易错点。做题的标准流程是三步：把目的地址写成 32 位二进制；对每条前缀逐位检查其前 k 位是否相同（k 为前缀长度）；在所有匹配者中取 k 最大者。A 题考验你对 /30 的理解——它只保留 30 位，最后 2 位随便，所以 .3 与 .0 同块；这正是点对点链路（两台路由器之间）的经典用法。C 题是 A 的镜像陷阱：.32 的第 26 位（倒数第二位）与 /30 前缀不符，于是"看起来很近"的地址反而只能落回默认路由——不要被前面几个字节的相似骗到。B、E 两题则展示"同一起点、不同长度"的嵌套前缀（/8 与 /10）如何同时成立，胜者永远是更长的那条。注意 E 题的关键位是**第 9 位**：/10 只比 /8 多约束两位，而 171.128.16.0 恰好在第 9 位上偏离 0，所以 /10 匹配失败。这种逐位比对的严谨性，与 6.042J 中验证"串是否属于某正则语言/前缀码"时的逐符号检查如出一辙——网络里没有"大概匹配"，只有"逐位精确匹配到前缀长度为止"。
