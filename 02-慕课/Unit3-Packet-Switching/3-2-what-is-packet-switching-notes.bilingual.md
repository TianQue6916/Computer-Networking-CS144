### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 1：引言</span>

本视频将讲述什么是分组交换（packet switching），以及互联网为什么使用分组交换。分组交换最早在 20 世纪 60 年代初由 Paul Baran 描述。分组交换描述的是：一个个信息分组（packet）如何被逐个地从源路由到目的地、横跨整个互联网——就像邮局投递信件一样。分组交换之所以极其重要，是因为一旦选择使用分组交换，它就决定了网络的许多性质。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 2：本讲大纲</span>

今天我将解释什么是分组交换，以及它为什么被选为互联网的基础。但首先，我需要介绍分组交换的前身——电路交换（circuit switching）。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 3：电路交换与传统电话网</span>

电路交换最常见的应用场景是传统有线电话网络。我们来走一遍从左边的话机拨打右边话机时发生的事情。两部电话各由一条专用线路连接到本地交换局（local exchange）。在早期，一屋子接线员用一块大型配线板（patch-panel）手工地把一部话机的专线与另一部话机的专线连接起来。关键点在于：从通话开始到结束，这条线路始终专属于这通电话。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 4：通话的三个阶段</span>

如今当然没有满屋子的接线员了。取而代之的是，这些自动电路交换机（circuit switch）为我们在这端电话与另一端朋友的电话之间建立电路。把一通电话想象成三个阶段会有帮助：

1. **建立阶段**：我们拿起听筒、拨出号码，这在两部话机之间创建了一条专用电路（dedicated circuit）。每个交换机维护状态，把入局电路映射到正确的出局电路上。
2. **通话阶段**：我们说话。在数字电话系统中，语音被采样、数字化，然后通过这条专用电路传输——语音的典型速率是 64 kb/s。我们的通话在整条路径上拥有一条专用电路（或称信道 channel），不与任何其他人共享。
3. **挂断阶段**：我们挂机时，电路被拆除，沿途各交换机上维护的状态也随之删除。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 电路交换的核心特征在这三个阶段里看得非常清楚：**状态在网络的中间节点里**。每个交换机都要记住"入局电路几号接到出局电路几号"，通话期间一直保留，挂断才释放——这与 CSAPP 第 11 章socket 编程的世界观恰好相反：互联网的中间路由器原则上不感知"连接"，连接状态（序列号、窗口、套接字）全部住在两端主机里。另外，64 kb/s 这个神奇的数字值得拆开看：语音的主要能量集中在 4 kHz 以内，根据采样定理至少需要 8 kHz 的采样率才能无失真恢复，每个样本用 8 bit 量化，于是 $8\,\text{kHz} \times 8\,\text{bit} = 64\,\text{kb/s}$——这是 PCM（脉冲编码调制）数字语音的标准速率，也是后面 3-9 讨论速率保证时"每条电路保底带宽"的历史由来。理解了"电路=预留的恒定速率管道"，你就明白为什么它对突发数据业务是浪费：安静时带宽照样占着。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 5：干线与"大肥管道"</span>

实际中，交换中心之间的干线（trunk line）速度非常快——也就是说数据速率很高。最慢的也运行在 2.4 Gb/s，而今天最快的达到 40 甚至 100 Gb/s。有时你会听到人们把这些干线叫作 "big fat pipes"（大肥管道），因为它们能发送海量数据。但这些"大肥管道"其实是一根比你的头发丝还细的、又小又细的光纤。成千上万通电话以各自独立的电路共享同一条城际干线。要记住的关键点是：每一通电话都有自己专属的 64 kb/s 电路，不必与任何人分享。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "几千路电话共享一根光纤、每路却各有专属电路"靠的是复用（multiplexing）：在数字电话网里，标准做法是时分复用（TDM）——把时间切成一个个时隙，第 1 路占时隙 1、第 2 路占时隙 2，如此循环，每路都拿到自己固定的一格。这套机制高效的前提是每路流量恒定：语音确实大致如此。但把它套在数据业务上就露馅了：网页浏览、文件传输都是"突发一阵、停顿一阵"，为突发流量预留固定电路，意味着停顿时带宽被白白浪费。这个矛盾正是分组交换的出发点——不预留，大家按需排队竞争，网络统计复用（statistical multiplexing）地把闲时带宽让给忙的人。3-5 讲的确定性队列模型和 3-5 之后"统计复用"一节，就是把这笔账算给你看。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 9：分组交换的工作方式</span>

在分组交换中，没有承载我们数据的专用电路。取而代之的是，我们把一块数据加上一个首部（header）后发送，并把它称为一个分组（packet）。首部中包含该分组要去往的地址，就像信封告诉邮局这封信寄往哪里。一个分组交换网络由终端主机（end host）、链路（link）和分组交换机（packet switch）组成。当我们发送一个分组时，它被逐跳（hop-by-hop）路由到目的地。每个分组交换机在自己的本地转发表（forwarding table）中查找分组首部里的地址。例如，这个分组的地址是 B：当我们发送它时，第一台路由器在本地表中查找地址 B，看到下一跳是交换机 S2；S2 和 S4 做同样的事，分组最终被交付给 B。

在互联网中，有几种不同类型的分组交换机。有些被称为路由器（router）或网关（gateway），另一些则被称为以太网交换机（Ethernet switch）。我们稍后会深入学习它们各自的结构。现阶段你只需要知道：它们都是分组交换机的类型，都依据首部中的目的地址转发分组。

🎥 *CS144 教授在视频中解释: "分组交换最早由保罗·巴伦在二十世纪六十年代的早期描述。它描述了信息包是如何逐个通过互联网路由到目的地的，就像信件由邮局递送一样"*（字幕来源：040 - p39 3-2 Packet Switching - Principles What is packet switching.zh.srt）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "查表→转发"这四个字是整台路由器的心脏，值得现在就建立精确的图像：交换机收到分组后，取出首部里的目的地址，在本地转发表里查找，得到"从哪个端口发出去"。这里查表的方式在 Ethernet 交换机和 IP 路由器上截然不同——前者是精确匹配（地址必须完整出现在表里），后者是最长前缀匹配（longest prefix match，多个表项都能匹配时选最具体的那个），这个区别会在 ps_switching 两讲里展开成算法问题（哈希表精确查找对二进制 trie/TCAM 前缀查找），你可以先用 CLRS 的哈希表和 6.042J 的树形结构预热直觉。另外注意"存储转发"隐含的时间代价：交换机要等整个分组收完才能查表转发，于是每个交换机都贡献一份"传输时延"，这正是 3-3 端到端时延公式里每一跳都有 $p/r_i$ 一项、以及 3-5 中"把大报文切成小分组反而更快"的根本原因。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 10：无数分组共享链路</span>

当然，任一时刻互联网上都有无数分组在流动，它们各自被逐跳独立路由。这些分组与去往不同目的地的其他分组一起，共享路径上的所有链路。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 14：分组交换的好处</span>

把报文拆成分组允许在所有链路上并行传输，从而降低网络时延。概括起来，分组交换网络的好处如下：

- 它们高效地使用带宽：一条干线链路占用的资源少于其所有支路之和，因为它们复用并节约带宽；
- 中间节点几乎没有状态；
- 它们健壮（robust），有人声称它们被设计成能承受核打击；
- 不存在一个需要向它申请许可才能做实验的中央权威。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这份好处清单每一条都值得对着电路交换反着读一遍。"中间节点几乎没有状态"对应电路交换每台交换机必须维护的电路映射表——无状态意味着交换机崩溃重启也不影响"连接"，也意味着新应用不需要网络批准就能上线，这就是"没有中央权威"的技术底座，也是 Unit 1 端到端原则（end-to-end principle）在体系结构上的直接体现。"承受核打击"的说法则需要一点辨析：Baran 1964 年的设计确实以"分布式通信在部分节点被毁后仍能幸存"为目标，但 ARPANET 本身并不是按军用抗毁标准建造的，这个流传甚广的说法更像一种文化神话——不过神话本身也影响了互联网"去中心化"的气质。最后一条"鼓励坏行为"的反面没有写在这里：FIFO 共享队列对带宽贪吃者不加惩罚，这个激励问题会在 3-9 的速率保证里正面处理。
