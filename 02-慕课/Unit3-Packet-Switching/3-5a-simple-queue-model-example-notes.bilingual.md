### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 2：例题与到达/离开过程</span>

<span style="color:#c0392b;">**例题：**</span>每秒的开头，一列 100 比特的"比特列车"以 1000 bit/s 的速率到达一个队列；队列的离开速率为 500 bit/s。队列逐比特被服务，可以假设缓冲区无限大。**(a) 队列的平均占用（occupancy）是多少？**

> <span style="color:#c0392b;">**解答 (a)：**</span>累积到达与离开过程如图所示。先看红色显示的累积到达过程 $A(t)$：在最开始的 $1/10$ 秒内，100 比特以 1000 bit/s 的速率到达；直到 1 秒时刻之前不再有到达，届时又有新的 100 比特到达。再看绿色显示的离开过程 $D(t)$：只要第一列比特列车开始以 1000 bit/s 到达，比特就开始离开——因为题目说队列是逐比特被服务的。如果我们必须等整个分组收齐才能服务，离开过程此时还不会开始上升。由于离开速率 500 bit/s 是到达速率的一半，这些比特需要 0.2 秒才能全部离开。队列因此不断积压，在 0.1 秒时达到峰值。
>
> 把队列占用 $Q(t)$ 看成时间的函数。队列占用就是 $A(t)$ 与 $D(t)$ 之间的**竖直距离**——到此为止已到达的比特数减去已离开的比特数。在最初的 0.1 s 内队列随新比特到达而增长，在 0.1 s 时达到 50 bit 的峰值；随后在 0.1 s 到 0.2 s 之间排空，直到变空、所有比特离开；队列空置 0.8 s 后，同样的过程重复。于是可以立刻算出队列的时间平均占用：队列在 0.2 s 内平均占用 25 bit，在 0.8 s 内占用为 0，故时间平均为：

```math
\bar Q \;=\; \frac{0.2\times 25 \;+\; 0.8\times 0}{1} \;=\; 5\ \text{bit}
```

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这道题的图解法——到达曲线 $A(t)$ 与离开曲线 $D(t)$ 之间，竖直距离是队列占用 $Q(t)$、水平距离是排队时延 $d(t)$——是本单元最值得练到条件反射的工具，ps_delay_model 一讲会把它正式化。这里先埋一个验证手段：你正在学的概率论稍后会讲到利特尔法则（Little's law）$L=\lambda W$（平均占用 = 平均到达率 × 平均时延），现在就能用它验算本题：长期平均到达率 $\lambda = 100\ \text{bit} / 1\ \text{s} = 100\ \text{bit/s}$（每秒 100 比特），下一问将算出平均时延 $W = 0.05\ \text{s}$，于是 $L = 100 \times 0.05 = 5\ \text{bit}$，与 (a) 的答案严丝合缝。两种完全不同的算法（对时间平均 vs 对比特平均）得到同一个数，不是巧合——这正是 Little's law 的威力：它把"队列里有多少"与"每个顾客等多久"这两个看似无关的量锁在一起，且不依赖任何到达过程假设。

🎥 *CS144 教授在视频中解释: "队列占用率是 A(t) 和 D(t) 之间的垂直距离，它仅仅是到达到这个点的位元数量，减去已经离开的位元"*（字幕来源：044 - p43 3-5a Simple Queueing Model Example.zh.srt）

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 3：问题 (b)——比特的平均时延</span>

第二个问题是：<span style="color:#c0392b;">**队列中一个比特的平均时延是多少？**</span>

> <span style="color:#c0392b;">**解答 (b)：**</span>再次观察 $A(t)$ 与 $D(t)$ 的演化。时刻 $t$ 到达的比特所见到的时延是 $d(t)$——两条曲线之间的**水平距离**。时刻 0 到达的第一个比特没有经历任何时延；而 0.1 s 时到达的比特要经历 0.1 s 的时延。注意 0.1 s 之后不再有比特到达，所以考虑"0.1 s 到 1.0 s 之间到达的比特"的时延没有意义——我们把概率条件在"比特到达"这一事件上，而它只发生在每秒的前 0.1 秒。因此，到达队列的比特所见的平均时延就是 $0.05\ \text{s}$（到达时刻在 $[0, 0.1]$ 上均匀分布，时延随到达时刻线性地从 0 增长到 0.1 s，取平均得 $\frac{0.1}{2} = 0.05\ \text{s}$）。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "(b) 的答案要条件在'比特到达'上"这句话，正是概率论里条件期望（conditional expectation）的教科书场景：我们求的不是"任意时刻的时延"（那样大部分时刻没有比特到达，会被 0 时延稀释），而是"一个到达的比特所经历的时延"，即 $E[\text{时延} \mid \text{到达}]$。到达时刻在 0.1 秒窗口内均匀分布、时延 $d$ 随到达时刻线性增长到 0.1 s，求平均得到三角形重心对应的 0.05 s。这里有个精度更高的理解：对到达时刻均匀分布的比特而言，时延的分布是 $[0, 0.1]$ 上的均匀分布（一一对应），所以期望就是区间中点。当你之后在 M/M/1 这类随机模型里看到"平均时延"时，同样要问一句：是 unconditional 还是 conditional？网络测量里的"平均分组时延"几乎总是后者——因为观测只发生在分组到达时，这与本题的条件化完全一致。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 4：问题 (c)——随机到达间隔</span>

仍是同一个队列，第三个问题是：<span style="color:#c0392b;">**如果这列 100 比特的列车以随机间隔到达（平均每秒一列），队列的平均占用会比 (a) 更高、更低还是相同？**</span>

> <span style="color:#c0392b;">**解答 (c)：**</span>时间平均占用会**更高**。在 (a) 中列车确定性地到达时，两列列车从不重叠，队列里从不会同时出现两列列车的比特。但如果它们随机到达，队列里就可能同时有两列甚至更多列列车的比特，把占用（从而平均占用）推高。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 5：为什么——一个反例演示</span>

这可能令人意外。我们用一个例子看看为什么这是真的。

考虑两种情形。**情形 1**：假设列车随机到达，但任何两列都不重叠——平均队列占用将与之前相同，即 5 bit。**情形 2**：一旦有两列列车重叠，哪怕只有一次，平均值就会上升。看这个例子：红线显示我们假定在时刻 0 到达的第一列列车的队列占用。设第二列列车在 0.1 s 时到达——此时队列里还有第一列列车留下的 50 bit。队列将继续增长，因为比特到达的速度是离开速度的两倍；队列要到 0.4 s 才能排空。如果这种情形每 2 秒发生一次，到达速率与之前相同，但时间平均占用变为：0.4 s 内平均占用 50 bit，随后 1.6 s 内为空。求时间平均要除以 2 秒：

```math
\bar Q \;=\; \frac{0.4\times 50 \;+\; 1.6\times 0}{2} \;=\; 10\ \text{bit}
```

是之前（5 bit）的两倍。为什么？因为队列只能以 500 bit/s 的速率排空，所以它不仅涨到之前的两倍高，排空也要花两倍长的时间——表示队列非空时段的那个三角形，面积是之前的四倍。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> "面积翻四倍、时间平均翻两倍"这组数字里藏着排队论最重要的一条定性规律：**到达越突发，队列越糟**。拆开看很清晰：到达速率相同（都是平均每秒 100 bit），但把两列车挤到一起到达，峰值高度翻倍（100 bit）、非空时长翻倍（0.4 s），三角形面积 $\frac{1}{2}\times\text{底}\times\text{高}$ 翻四倍；分摊到更长的时间窗后平均值翻倍。极端化这个思想实验：若所有比特在零时间内同时砸进队列，峰值就是 200 bit。ps_queue_props 的队列性质 #1"突发性增加时延"与 #2"确定性最小化时延"讲的就是这件事，而"以固定速率匀速放行"的整形思路会化身漏桶（leaky bucket）在 3-10 的时延保证里正式登场——你会看到 (d) 小问里第一个队列其实已经是一个天然的流量整形器。对学过概率的你，还可以用矩的语言说：固定均值下，到达间隔方差越大，队列长度的期望越大。

### <span style="color:#2471a3;">**[section]**</span> <span style="color:#c0392b;">Slide 6：问题 (d)——级联第二个队列</span>

问题的第四部分：<span style="color:#c0392b;">**如果队列离开的比特被送入第二个相同的队列（离开速率同为 500 bit/s），第二个队列的平均占用是多少？**</span>

> <span style="color:#c0392b;">**解答 (d)：**</span>第二个队列的比特将以 500 bit/s 的速率到达、以 500 bit/s 的速率离开。换句话说，它永远不会积累比特，将始终为空（平均占用为 0）。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> (d) 的结论看似平淡，实则是本单元一条暗线的收口：第一个队列虽然"积压"，但它的输出流已经被彻底整形——离开速率恒为 500 bit/s、从不超速。把它接进一个同样 500 bit/s 的下游队列，下游自然永远为空。这正是"流量整形（shaping）换下游零排队"的原理：把到达过程的突发性在本地用队列消化掉，换来离开过程的确定性，下游（往往是更昂贵的资源）就不再需要缓冲。3-10 的时延保证机制用的正是这套逻辑——让源端满足漏桶约束 $A(t+T)-A(t)\le\sigma+\rho T$，路由器侧的 WFQ 队列才能给出有界时延。往更广处说，工业流水线、地铁限流、里程碑式的"削峰填谷"，都是同一个确定性队列模型在不同外衣下的重演；你在这里用一张 $A(t)$/$D(t)$ 图就能看穿它们。
